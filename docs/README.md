# 문서 지도

무엇을 어디서 보는지, 새 문서를 어느 폴더에 두는지 적는다 (2026-10-11 정리 — `docs/DECISIONS.md` 29장).
저장소 전체 그림은 루트 `README.md`, 안전 규칙·명령·작업 방식은 루트 `AGENTS.md`.

## 바로 아래 — 기준 문서

여러 문서와 코드 주석이 가리키는 문서라 자리를 옮기지 않는다.

| 문서 | 내용 |
|---|---|
| `API.md` | 웹 API 계약. 백엔드와 프론트가 같이 따른다 (API를 바꾸면 이 파일을 먼저 고친다) |
| `DECISIONS.md` | 작업자 공통 결정. 장 번호로 가리킨다 |
| `DEPLOY.md` | 배포와 CI/CD |
| `KIWOOM.md` | 키움 REST API 확인 결과 |
| `결정필요사항.md` | 남은 결정·확인과 다음 세션 시작점 |
| `교육용문서.md` | Agent 개념. 앱의 교육 화면이 이 파일을 빌드에 넣는다 (`frontend`의 `?raw` import, `deploy/nginx/Dockerfile`, `.dockerignore`의 `!docs/*.md`가 이 자리를 가정한다) |

## 새 문서를 둘 곳

- 바로 아래에는 위의 기준 문서만 둔다. 새 문서는 종류에 맞는 폴더에 둔다.
- 계획서는 `plans/`에 둔다. 구현이 끝나면 머리의 상태 줄을 고치고 정한 것은 `DECISIONS.md`에 옮긴다. 끝난 계획도 지우지 않는다.
- 시험·점검처럼 그날의 기록은 `records/`에 `이름_YYYY-MM-DD.md`로 둔다.
- 문서 속 경로는 저장소 루트 기준으로 적는다 (`docs/plans/TEAM_DEV_PLAN.md`). 파일을 옮기면 옛 경로를 저장소 전체에서 찾아 바꾼다.
