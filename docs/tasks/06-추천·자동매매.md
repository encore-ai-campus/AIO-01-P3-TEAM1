## 범위 — 핵심 Agent 워크플로우는 담당 2·3·4, 나머지는 시연 가능한 버전으로 먼저 만들었다

| 구분 | 무엇 | 누가 |
|---|---|---|
| 핵심 (손대지 않음) | AI 리포트의 Worker·출력 계약(2), Orchestrator·Guard·runner(3), AutoHealing·장애 주입·복구 지표(4) | 담당 2·3·4 (`02~04` 문서) |
| 이 문서 | 추천·리스크 미리 보기·계획 활성화(웹·Discord 링크)·자동매매 진행·웹 알림·Discord Webhook·화면, 그리고 담당 1·5의 일부(Webhook, 선별 저장·API, A4 PDF) | 2026-10-04에 시연 버전을 만들었다. 이후 유지·통합은 **담당 1**, 화면은 **담당 5** — 유지(B4~B7 포함)와 화면 → Claude가 구현 (2026-10-05) (1은 PR 합치기 등 통합, 5는 Claude가 합친 뒤 다듬기) |

핵심 워크플로우와 만나는 곳은 **한 군데**다: 리포트가 `completed`로 끝나면 엔진 루프의 "추천 수집" 단계가 `Report.results["report_agent"]`(출력 계약 `ReportDraft`)를 읽어
`verdict == "buy"`이고 `targets`의 진입·목표·손절이 `0 < stop < entry < target`이면 추천을 만든다. 담당 3이 따로 부를 함수는 없다.
그 전에는 지금 있는 **AI 교차검증 분석(`analysis`)의 BUY**와 **시연용 규칙 추천(`demo`, AI 아님 — 화면·Discord에 늘 표시)**으로 같은 흐름을 시연한다.

```
AI 리포트(report) · AI 분석 BUY(analysis) · 시연 규칙(demo)
        └→ Recommendation (팀 공용, validUntil까지) ─ 알림: 신청자(없으면 팀 전체) 웹 + Discord(서명된 활성화 링크)
              └→ 활성화 (웹 버튼 / Discord 링크 → 로그인 → 확인) ─ 넣을 돈은 사용자가(내 자금 % 또는 원) → 수량 계산, 리스크 엔진 assess_budget이 점검 (손익비 1.5·매수 가능 금액·총 한도 — 2026-10-11, DECISIONS 28장)
                    └→ TradePlan: active → entry_pending(진입 지정가, 그날 미체결이면 기한 안에서 재주문) → holding(목표·손절·기한 자동 감시) → closed
                                  (중단 → cancelled, 기한 → expired, 주문 불가 → failed)   단계마다 PlanEvent + 웹 알림 + Discord
```

## 시연 순서 (발표·영상용)

> 2026-10-04 합의로 화면 이름이 바뀐다 (`docs/DECISIONS.md` 13장): "추천" 탭 → **모의투자 탭의 "새 계획 제안"**(주소 `/recommendations`는 그대로), "계획 활성화" → **실행 확인(예산 → 수량·금액 → 체크리스트 셋) → "모의 자동매매 시작"**(B5),
> 서비스 이름 "모매매"(2026-10-07 바뀜, 전 이름 "종이배"·"AI 리포트 데스크"). 시연용 규칙 추천은 "연습용 예시 계획 (AI 아님)"으로 부르고 개발·시연 환경에서만 켠다 (배포는 리포트가 돌면 `AUTOTRADE_DEMO=off`, D-4). 아래 순서는 10/8 화면 동결 뒤 새 이름으로 고친다.

준비: 호스트 PC에서 `scripts/dev.sh`(마이그레이션 적용 + Django + 엔진 루프 + 프론트). Discord로도 보이려면 `.env`에 `DISCORD_WEBHOOK_URL`, `PUBLIC_BASE_URL`(팀원이 여는 프론트 주소).
각 팀원은 My Page → 알림 설정에 자기 Discord 사용자 ID를 넣으면 알림에 멘션된다.

1. **추천** 탭 → "시연용 추천 만들기"(종목 코드, 예 005930) — 또는 AI 분석(BUY)·AI 리포트가 끝나면 엔진 루프가 5초 안에 추천을 만든다.
   손으로: `cd backend && uv run python manage.py demo_recommend --symbol 005930` (팀 전체 알림), 선별 상위로: `manage.py auto_recommend --force`.
2. 추천 상세: 가격 사다리(손절–진입–목표, 지금 가격), 목표 수익률·손절률·손익비·확률·기대수익률, 근거·리스크, 출처 배지("시연용 · AI 아님" / "AI 리포트" / "AI 분석").
3. **활성화 카드**: 투자 금액(내 자금 % 또는 원, 필수 — 2026-10-11) → 리스크 엔진 미리 보기(수량·매수 금액·목표 도달 이익·손절 손실과 자산 대비 %) → "계획 활성화".
4. **Discord**: 채널에 온 추천 메시지의 "계획 활성화" 링크를 다른 팀원이 누름 → 로그인 → 같은 화면(파란 띠 "Discord에서 연 활성화 링크") → 활성화 → `via: discord`.
5. **내 자동매매**: 워크플로우(활성화 → 리스크 점검 → 진입 주문 → 체결 대기 → 보유 감시 → 청산)와 사건 타임라인. 정규장이면 지정가 도달 시 체결 → 목표·손절 시 청산, 단계마다 종·Discord 알림.
   정규장 밖이면 주문은 체결 대기로 남는다 (다음 정규장). 서버 없이 보이려면 `cd frontend && VITE_MOCK=1 npm run dev` — 활성화 6초 뒤 체결, 12초 뒤 목표가 청산이 흉내 난다.
6. "계획 중단": 체결 대기면 주문 취소, 보유 중이면 전량 매도(정규장 밖이면 매도 예약).

⑩ openclaw만 있어도 발송 ⑪ AI 글 속 멘션 무력화·embed 길이 제한·Discord ID는 ASCII 숫자만·보유 중 중단 두 번.
그대로 둔 것: 재주문 때 리스크 점검에서 막히면(지금 가격이 목표가 위 등) 그 계획은 `failed`로 끝난다 (계약에 적었다).

## 알려진 한계 (문서·발표에 그대로 적는다)

- Discord 활성화는 버튼이 아니라 **링크**다 (Webhook은 보내기만 된다. 봇은 만들지 않았다 — `docs/DECISIONS.md` 12-4). 링크를 눌러도 웹 로그인은 필요하다.
- 시연 추천은 AI가 아니다 (일봉 ATR 규칙). 화면·Discord·추천 내용에 늘 표시한다. 확률 0.45는 가정 값이다.
- 계획 하나 = 모의 주문 하나 = 포지션 하나. 같은 종목에 진행 중인 계획·주문이 있으면 활성화하지 않는다. 분할 매수·추가 매수는 없다.
- 알림은 팀 채널 하나로 간다 (개인 DM 없음). 멘션은 본인이 넣은 Discord ID를 믿는다 (소유 확인 없음).
- (B5) 실행 확인 체크리스트는 서버가 강제하지 않는다. `acknowledged`는 기록일 뿐이고, 체크리스트 없이 시작되지 않는 것은 화면 테스트로 보장한다.
