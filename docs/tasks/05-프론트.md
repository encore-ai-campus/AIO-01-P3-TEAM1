## 2026-10-05 UI/UX 개선 (Claude — 합친 뒤 5가 이 위에서 다듬는다)

결정과 규칙은 `docs/DECISIONS.md` 15장, 화면마다 카드 순서와 그 이유는 `docs/design/화면배치.md`.
- **화면 모드(다크)**: 마이 "화면 모드" 카드 `[기기 설정 · 밝게 · 어둡게]` + PC 왼쪽 메뉴 "어두운 모드" 스위치. 브라우저(localStorage `paper-theme`)에 저장, 기본은 기기 설정. 색은 `src/index.css` 토큰만 쓴다(`src/test/colors.test.ts`가 TSX의 #hex·rgb()를 막는다).
- **모션**: 짧고 차분한 토큰(100~320ms), 화면 전환은 불투명도만, 시트·접힘·토스트 닫힘 애니메이션, 미끄러지는 선택 표시, 버튼·행 누름 피드백(`press`·`press-row`), 움직임 줄이기면 끔.
- **앱 뼈대**: 새 화면은 맨 위에서 열고 뒤로 가면 위치 복원, 지금 탭 다시 누르면 맨 위로, 화면 이동 뒤 제목에 포커스·문서 제목, 토스트는 늘 맨 위 층, 화면 렌더 오류는 그 화면 안에서만.
- **배치**: 화면마다 여정·빈도·위계·엄지 영역·PC 2단 균형으로 순서를 다시 정했다(예: 홈은 내가 시킨 일(만드는 중·진행 중)을 최근 리포트 위로, 리포트 상세 PC는 [읽기 | 매매 계획] 2단, 마이는 주린이모드·진단을 한 카드로).
- **이름·로고**: 서비스 이름을 "종이배"로 바꿨다(사용자 요청 — `docs/DECISIONS.md` 15-7). **2026-10-07 이름을 "모매매"로 다시 바꿨다**(18장). **2026-10-08 로고를 종이배에서 ㅁ 블록 셋의 계단으로 바꾸고 워드마크·앱 인트로·로그인 부제를 새로 했다**(ju `f2d42db`, 27장). 로고는 `components/brand/BrandMark.tsx`(도형 `lib/brandShapes.ts` — PC 메뉴·모바일 홈 머리·로그인·부팅), 파비콘·홈 화면 아이콘, PDF 머리·Discord 머리말까지. 발표 자료에도 새 이름·로고를 쓴다(로고 원본 SVG는 `BrandMark.tsx`·`public/favicon.svg`, 인트로 영상은 `VITE_MOCK=1`의 `/ui/brand`를 화면 녹화).

## 화면 구성 (2026-10-04 결정)

발표 흐름: 신청(장애 주입 켬) → 상세로 이동, "실행 과정" 탭에서 그래프가 실시간으로 바뀜 → 노드의 시도 이력·"자동 복구" → 실행 요약 띠 → "리포트" 탭(본문·PDF) → 관리자 화면 `/ops`의 복구 지표 (2026-10-04: "리포트" 메뉴를 8번 연속 눌러 연다).
`docs/API.md`는 바꾸지 않는다 (목록에 복구 건수는 넣지 않는다. 복구 수치는 상세와 관리자 화면 `/ops`에서 본다).

**`/reports/:id` (상세)** — 위에서 아래로:
1. 머리 카드: 종목·상태·신청자·시각, "자동"·"주입" 배지, 전달 방식.
2. **실행 요약 띠** (탭과 무관하게 항상): 실행 중엔 현재 단계, `recovery`로 "장애 n · 자동 복구 n · 복구 시간 · 비용". 장애가 없으면 "장애 없음".
3. 탭 3개 (`?tab=`):
   - **리포트** — 본문, PDF 내려받기, 실패면 사유와 "다시 신청". 본문이 아직 없으면 "실행 과정 보기"로 안내.
   - **실행 과정** — 실행 계획 그래프 → Trace 타임라인.
   - **자세히** — Shared State, 정책 안내, 개념 문서, 예시 Trace 재생 (예시를 켜면 "실행 과정" 탭으로 옮기고 예시 띠를 보인다).
   - 기본 탭: `requested`·`running`이면 "실행 과정", 끝났으면 "리포트". 보는 중에 완성되면 탭을 강제로 바꾸지 않고 요약 띠에 "리포트 완성 · 보기" 버튼.
4. 그래프 노드는 **압축형**: 제목 + 상태 + 시도 이력 칩 한 줄 + "자동 복구"·"주입" 배지. goal·id·출력 계약·Provider·소요는 노드를 누르면 펼친다.
5. 타임라인은 **문장형**: 기본은 "주요 사건"(실패·재시도·전환·완료·포기·검토 반복·Join/Handoff 막힘·시작과 끝), "전체" 토글로 모든 사건과 원본 action·details.

## 주의

- 화면은 **Trace와 `recovery`만 보고** 그린다. 같은 사건을 두 가지로 해석하지 않게 `src/lib/recovery.ts` 한 곳에만 셈법을 둔다 (백엔드 `stats.py`와 9절 규칙이 같다).

- 모바일 우선, PC에서도 보기 좋게 (Tailwind). 토스증권 스타일을 유지한다.
- 검사: `npx eslint . && npx tsc --noEmit && npx vitest run && npx vite build`. CI가 같은 검사를 돈다.
- PDF의 차트는 엔진 규칙(표준 라이브러리만)을 따른다 — SVG를 문자열로 만든다. `backend/`라서 외부 패키지를 쓸 수는 있지만 넣지 않는다 (엔진 컨테이너에서도 같은 코드가 돈다).
- 글자 수를 줄인다: 뉴스 원문·긴 비평은 PDF에서 빼고 웹 상세에서 본다.
- (2026-10-04) 발표 시연은 약 8분: 쉬운 보기 2분 30초 → 같은 리포트를 "이 화면만 자세히 보기"로 뒤집어 전문가 보기 4분(Agent 역할·Join Guard·Handoff·검토 RETRY → PASS·진행 기록의 실패 → 재시도 → 대체 모델·`/ops` 복구 지표·실패 시나리오) → 파이프라인 1분 30초 (컨셉 계획 11장). 가짜 API 화면을 쓰면 "가짜 API"로 표시한다.
