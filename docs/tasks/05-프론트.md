## 화면 구성 (2026-10-04 결정)

발표 흐름: 신청(장애 주입 켬) → 상세로 이동, "실행 과정" 탭에서 그래프가 실시간으로 바뀜 → 노드의 시도 이력·"자동 복구" → 실행 요약 띠 → "리포트" 탭(본문·PDF) → `/reports/health`.
`docs/API.md`는 바꾸지 않는다 (목록에 복구 건수는 넣지 않는다. 복구 수치는 상세와 `/reports/health`에서 본다).

**`/reports/:id` (상세)** — 위에서 아래로:
1. 머리 카드: 종목·상태·신청자·시각, "자동"·"주입" 배지, 전달 방식.
2. **실행 요약 띠** (탭과 무관하게 항상): 실행 중엔 현재 단계, `recovery`로 "장애 n · 자동 복구 n · 복구 시간 · 비용". 장애가 없으면 "장애 없음".
3. 탭 3개 (`?tab=`):
   - **리포트** — 본문, PDF 내려받기, 실패면 사유와 "다시 신청". 본문이 아직 없으면 "실행 과정 보기"로 안내.
   - **실행 과정** — 실행 계획 그래프 → Trace 타임라인.
   - **자세히** — Shared State, 정책 안내, 개념 문서, 예시 Trace 재생 (예시를 켜면 "실행 과정" 탭으로 옮기고 예시 띠를 보인다).
   - 기본 탭: `requested`·`running`이면 "실행 과정", 끝났으면 "리포트". 보는 중에 완성되면 탭을 강제로 바꾸지 않고 요약 띠에 "리포트 완성 · 보기" 버튼.
4. 그래프 노드는 **압축형**: 제목 + 상태 + 시도 이력 칩 한 줄 + "자동 복구"·"주입" 배지. goal·id·출력 계약·Provider·소요는 노드를 누르면 펼친다.
5. 타임라인은 **문장형**: 기본은 "주요 사건"(실패·재시도·전환·완료·포기·검토 반복·Join/Handoff 막힘·시작과 끝), "전체" 토글로 모든 사건과 원본 action·details.

**`/reports` (목록)** — 위에서 아래로: 복구 지표 미니 카드(자동 복구율·평균 복구시간 → `/reports/health`) → [신청 카드(장애 주입 포함) | 팀 리포트(필터 칩 전체·자동·장애 주입, 배지, 비용)] → 오늘의 선별 결과 → (접힘) 실행 계획 미리 보기 → (접힘) 교육용 문서.

**`/reports/health`** — 기간 칩 → 큰 숫자 2개 → 유형별 누적 막대(복구/미복구) → Worker별 막대 → 최근 사례(모바일은 카드 목록, PC는 표).

**종목 상세** — "AI 리포트 신청"을 누르면 같은 신청 폼(장애 주입 포함)이 바텀시트(PC는 모달)로 열린다.

## 주의

- 화면은 **Trace와 `recovery`만 보고** 그린다. 같은 사건을 두 가지로 해석하지 않게 `src/lib/recovery.ts` 한 곳에만 셈법을 둔다 (백엔드 `stats.py`와 9절 규칙이 같다).
- SSE는 저장소가 아니다 (`src/api/reports.ts`의 Snapshot + SSE 합치기를 그대로 쓴다). 새 사건 종류를 더해도 `useReportLive`는 고칠 필요가 없어야 한다.
- 모바일 우선, PC에서도 보기 좋게 (Tailwind). 토스증권 스타일을 유지한다.
- 검사: `npx eslint . && npx tsc --noEmit && npx vitest run && npx vite build`. CI가 같은 검사를 돈다.
- PDF의 차트는 엔진 규칙(표준 라이브러리만)을 따른다 — SVG를 문자열로 만든다. `backend/`라서 외부 패키지를 쓸 수는 있지만 넣지 않는다 (엔진 컨테이너에서도 같은 코드가 돈다).
- 글자 수를 줄인다: 뉴스 원문·긴 비평은 PDF에서 빼고 웹 상세에서 본다.
