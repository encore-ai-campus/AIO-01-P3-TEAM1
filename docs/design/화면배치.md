# 화면 배치와 근거 (2026-10-05)

화면마다 카드·버튼이 **왜 그 자리에 있는지**를 적는다. 정보 구조(하단 탭, 화면 목록)는 `docs/plans/컨셉변경계획.md` 4장이 정했고,
이 문서는 그 안의 **배치 순서와 이유**를 적는다. 2026-10-05 UI/UX 개선(`docs/DECISIONS.md` 15장)에서 모든 화면을 감사·수정한 결과다.
화면 배치를 바꾸면 이 문서의 해당 줄도 함께 고친다.

## 0. 배치 원칙 (모든 화면 공통)

1. **여정 순서**: 서비스 여정은 ① 만들기(리포트) → ② 검토 → ③ 실행(모의 자동매매)이다. 화면마다 지금 사용자의 **다음 한 걸음**이 첫 화면에 온다.
2. **결론 먼저**: 리포트·분석·복기는 결과 → 행동 → 근거 순서다. 근거는 행동 아래나 접힘 안에 둔다.
3. **다시 온 사람의 첫 질문**: "내가 시킨 일이 어떻게 됐나"(만드는 중인 리포트·진행 중인 자동매매)를 팀 피드·참고 자료보다 위에 둔다.
4. **빈도와 위험**: 자주 쓰는 것은 위·엄지 영역에, 한 번 정하면 끝나는 설정은 아래에 둔다. 위험한 동작(멈추기·로그아웃)은 이동 링크와 떼어 맨 아래에 두고, 누르기 전에 결과를 한 줄로 말한다.
5. **모바일 엄지 영역**: 주 행동은 화면 가운데 아래·하단 탭 바로 위에 둔다. 시트·폼의 제출 버튼과 금액 확인은 바닥에 붙여 입력하는 동안에도 보이게 한다. 키보드가 아래 절반을 덮는 화면(검색)은 입력칸과 첫 결과를 위에 둔다.
6. **PC 2단 문법**: 왼쪽 넓은 열은 보기·읽기·감시, 오른쪽 340~380px 열은 하기·상태·다음 행동이다. 같은 탭 안의 화면은 같은 문법을 쓴다.
   오른쪽 열을 따라오게(sticky) 할 때는 화면 높이 안에 들어올 때만 그렇게 하고, 길면 열 안쪽 스크롤이나 바닥 고정으로 주 버튼이 화면 밖에 묶이지 않게 한다.
7. **DOM 순서 = 모바일 순서**: PC 2단은 grid 배치로만 바꾸고 `order-*`로 순서를 뒤집지 않는다. 키보드·화면 읽기 순서가 화면 순서와 같아야 한다.
8. **자리를 고정한다**: 있고 없음에 따라 섹션이 생기고 사라지면 아래가 밀린다. 비어도 한 줄을 남기고(예: "진행 중인 모의 자동매매가 없어요"), 늦게 오는 안내는 펼침(Collapse)으로 들어온다.
9. **같은 기능은 같은 자리·같은 말**: 보기 전환(쉬운↔전문가), '전체 보기 ›', 섹션 머리(카드 밖 19px 제목 = 목록 섹션, 카드 안 17px = 한 덩어리 카드), 빈 상태(아이콘·제목·설명·다음 행동)를 화면마다 같게 쓴다.
10. **좁은 PC(1024~1279px)**: 2단이 본문 열을 옆 열보다 좁게 만들면(숫자가 자릿수 중간에서 줄바꿈) 그 화면은 한 열로 둔다(홈은 680px 한 열, 2단은 1280px부터).

## 1. 앱 뼈대

| 기기 | 순서 | 이유 |
|---|---|---|
| 모바일 | 고정 머리[뒤로·제목·화면 동작·종] → 본문 → 출처 줄 → 하단 탭[홈·종목·리포트·모의투자·마이] | 탭 순서가 여정과 같다(종목 고르기 → ① ② 리포트 → ③ 모의투자). 핵심인 '리포트'가 가운데라 두 엄지가 닿는다. 종은 자주 열지 않아도 배지가 늘 보여야 해 오른쪽 위. 출처 줄은 약관상 매 화면 필요하지만 위계가 가장 낮아 맨 끝(짧은 화면에서도 바닥에 붙는다). |
| PC (1024px~) | 왼쪽 메뉴[브랜드 → 홈·종목·리포트·모의투자·알림·마이 → (아래) 어두운 모드 스위치 → 닉네임] + 본문 | 메뉴 순서가 하단 탭과 같아 기기를 바꿔도 머릿속 지도가 같다. PC에는 위쪽 막대가 없어 알림은 메뉴 안, 개인 영역인 '마이' 바로 위. 어두운 모드는 '내 환경' 설정이고 드물게 쓰니 계정 블록 곁 아래 모서리(발표 때 프로젝터에서 바로 바꾸는 데도 쓴다). |

- 홈 머리: 모바일은 서비스 이름(로고 + "모매매")을 보이고 h1 "홈"은 화면 읽기에만 둔다. 아래 탭이 이미 "홈"이라 같은 말이 겹치기 때문이다. PC는 "홈" 제목.
- 화면 머리에는 [뒤로·제목·종]만 두고, 보기 전환은 내용 쪽(리포트 머리 카드·홈 맨 아래)에 둔다 — 360px에서 긴 종목명이 잘리지 않게.
- 토스트: 모바일은 하단 탭·주문 바 바로 위(방금 누른 버튼 근처), PC는 본문 열 가운데 아래. 시트가 열려 있으면 화면 위쪽. 늘 맨 위 층.
- 연결이 끊기면 화면 아래(모바일은 하단 탭·구매 바 바로 위, PC는 본문 열 아래)에 한 줄로 알린다 — 위쪽 머리·검색칸·탭 줄을 덮지 않고 스크롤해도 늘 보이게. 아래 칸은 하단 바 → 진단 폼 바닥 → 연결 띠 → 토스트 순으로 쌓인다.
- 404: 아이콘 → 제목 → 설명·요청 주소 → 큰 '홈으로' → 보조 '리포트 보기'. 막힌 사람에게는 다음 행동이 가장 중요하다.
- 로그인: (앱을 `/`·`/login`으로 열 때 5초 인트로가 먼저 덮는다 — `docs/DECISIONS.md` 27장) 정체성(로고 56px → 워드마크 → 부제 "여러 AI가 함께 검증하는 모의투자") → 가치(설명 한 줄 + 3단계 칩) → 입력 → 결정(로그인) → 안심('실제 주문은 나가지 않아요'). 가로 가운데 정렬, 같은 말을 두 번 하지 않는다. 오류 한 줄 자리를 미리 잡아 화면이 흔들리지 않는다.

## 2. 홈 (`/`)

| 보기·기기 | 순서 |
|---|---|
| 쉬운 보기 모바일 | 머리(브랜드) → 3단계 안내(가로 스테퍼·지금 단계·CTA·예시 칩) → 만드는 중인 리포트(있을 때) → 진행 중인 모의 자동매매(늘 같은 자리, 비면 한 줄) → 최근 AI 리포트 → 오늘의 내 종목 뉴스(국내 보유가 있을 때) → 내 자산 → 최근 알림 → 랭킹 → [이 화면만 자세히 보기 · 3단계 안내 다시 보기] |
| 쉬운 보기 PC(1280~) | 왼쪽[3단계 안내 → 만드는 중 → 진행 중 → 최근 AI 리포트 → 내 종목 뉴스] \| 오른쪽 360[내 자산 → 최근 알림 → 랭킹] |
| 전문가 보기 모바일 | 머리 → 내 자산(카드 전체가 링크) → 장 상태 칩 한 줄 → 만드는 중 → 진행 중 → 새 계획 제안 → 최근 AI 리포트 → 내 종목 뉴스(요약형) → AI 교차검증 분석 4장 + 전체 보기 → 랭킹 → [이 화면만 쉽게 보기] |
| 전문가 보기 PC(1280~) | 왼쪽 360 sticky[내 자산 → 검색 → 장 상태] \| 오른쪽[만드는 중 → 진행 중 → 새 계획 제안 → 최근 AI 리포트 → 내 종목 뉴스 → 교차검증 분석 2×2 + 전체 보기 → 랭킹] |
| 1024~1279px | 모바일과 같은 순서의 680px 한 열 |

- 3단계 안내는 사용자의 진행 상태를 따라간다(✓ 한 단계 / 지금 / 다음). 지금 할 일 하나와 버튼 하나만 남겨 버튼이 엄지 높이에 온다. 다 해 보면 한 줄로 줄어든다.
- "내가 시킨 일"(만드는 중·진행 중)을 팀 피드(최근 리포트 = ② 검토 재료)보다 위에 둔다(원칙 3).
- 전문가 PC의 sticky 열에는 스크롤 내내 볼 것(돈·검색·장 상태)만 담아 680px 높이 화면에도 잘리지 않는다. 오른쪽 피드는 진행 중인 일 → 할 수 있는 일 → 참고 → 사회적 요소(랭킹) 순이다.
- 모바일 전문가 보기의 검색 막대는 뺐다 — 머리 돋보기·'종목' 탭과 입구가 겹친다.
- 보기 전환은 '이 화면을 어떻게 볼지'라는 설정이라 맨 끝에 둔다. 위로 올리면 첫 화면의 3단계 안내가 밀린다.

| 리포트 만드는 중 | 기다린 시간은 늘 "신청한 지 n분", 걸린 시간은 "보통 1~3분 걸려요"(최근 완성 리포트 범위). 검토 AI가 고쳐 쓰게 하면 쓰기 단계 아래 "검토 AI가 고쳐 쓰라고 해서 다시 쓰는 중이에요", 검토 단계는 "고친 글을 다시 봐요". 막대 n/5는 줄지 않는다 |
