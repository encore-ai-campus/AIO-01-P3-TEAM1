## 1. 새 컨셉

### 1-1. 누구의 어떤 문제를 푸나

- **대표 페르소나**: "민지, 27세. 주식 앱을 깔았지만 무엇을 사야 할지 모르고, 증권사 리포트는 용어가 어려워 끝까지 못 읽는다.
  **실제 돈을 넣기 전에** 리포트 읽기와 '정한 가격에 사고 정한 가격에 파는' 계획 매매를 연습해 보고 싶다." (모의 투자 = 연습 도구)
- **문제 셋**
  1. 전문가 리포트는 **어렵다** — 용어·숫자가 많고, 결론이 내 상황(내 계좌로 얼마를 사고, 얼마를 벌거나 잃나)으로 바뀌지 않는다.
  2. AI 답은 **믿기 어렵다** — 근거가 맞는지, 중간에 오류가 난 건 아닌지 알 수 없다.
  3. 알아도 **실행이 어렵다** — 정한 가격에 사고, 목표·손절에서 파는 것을 계속 지켜볼 수 없다.
- **약속 (가치 제안)**
  1. **쉽게 만든다**: 종목을 고르고 "AI 리포트 만들기" 한 번. 여러 AI가 시세·재무·뉴스를 나눠 조사해 증권사 리포트 구성(투자의견·목표가·근거·위험·지표·재무·뉴스/공시·검토 의견)으로 쓴다.
  2. **믿고 검토한다**: 검토 AI가 주장과 근거를 대조해 통과한 리포트만 보여 준다. 숫자는 쉬운 말과 "내 계좌로는"으로 풀어 준다.
     AI 하나가 응답하지 않으면 다른 AI로 바꿔 계속 만들고, 그래도 안 되면 이유를 알려 주고 담당자에게 알린다.
  3. **안전하게 연습한다**: 확인 체크리스트를 거쳐 버튼 하나로 모의 자동매매를 시작하면, 정한 가격에 사고 목표·손절에서 판다. 단계마다 알림이 온다.
- **"전문가급"의 뜻**: 위 약속 ①의 여덟 가지 구성을 갖췄는지로 말한다 (품질을 시험하지 않은 채 "전문가 수준"이라고 주장하지 않는다).
  화면·발표 자료의 바깥 문구는 "증권사 리포트 구성을 갖춘 AI 리포트"로 쓴다.
- **대표 시나리오 셋** (평가 가이드 1단계 "실패·지연·결과 불일치"까지):
  ① 정상: 만들기 → 검토 통과 → 실행. ② 복구: 뉴스 AI 장애 → 대체 모델로 완성 → 실행. ③ 실패: 필수 AI 전부 실패 → "만들지 못했어요"와 이유 + 담당자 알림(수동 개입).

### 1-2. 과제(에러 자가 치유 멀티 에이전트)와의 관계 — 컨셉은 "겉", 과제는 "엔진"

| 사용자가 보는 단계 | 뒤에서 일하는 것 (과제 요소) | 장애가 나면 사용자에게 보이는 것 |
|---|---|---|
| ① 만들기 | Orchestrator(Supervisor) → 조사 Agent 셋(Executor, 병렬) → Join Guard → 작성 Agent | "뉴스를 읽는 AI가 늦어 다른 AI가 이어받았어요" (재시도·대체 모델·Circuit Breaker) |
| ② 검토 | 검토 Agent(Critic, PASS·RETRY·FAIL) → (Handoff) 리스크 점검 Agent, 입력 Guard | "검토 AI가 근거가 약한 문장을 찾아 한 번 고쳐 쓰게 했어요", 실패면 이유와 "다시 만들기" |
| ③ 실행 | 결정론적 실행 (AI 아님): 리스크 엔진(수량·한도) → 모의 체결기 → 알림 | 실행 불가·미체결·만료·체결·청산을 쉬운 말 알림으로 |
| 모든 단계 공통 | Planner = 실행 계획(`team_definitions.yaml`), Memory Keeper = Shared State·Trace(`state.py`) | 진행 단계 표시와 "진행 기록"(전문가 보기) |
| 서비스 전체 | Docker·CI/CD(테스트 실패 시 배포 차단)·인프라 장애(DB 중단·엔진 재시작·SSE 끊김·Discord 실패) | 관리자 화면(`/ops`)과 파이프라인 기록 |

산출물 3종의 내용과 증빙은 그대로다. 설계서 ①의 "목적과 대표 사용자 시나리오"가 이 컨셉과 1-1의 시나리오 셋이 된다.

### 1-3. 하지 않는 것

- 실주문 없음 (모의 계좌만). 투자 자문·수익 보장이 아니다. **면책 문구는 한 문장으로 통일**해 화면(리포트·실행 확인)·PDF·Discord 메시지·발표 영상에 같이 쓴다:
  "이 리포트는 AI가 만든 참고 자료이며 투자 권유가 아닙니다. 모든 매매는 모의 계좌에서만 이뤄집니다."
- AI는 제안만 한다. 수량·실행 가능 여부·체결은 코드가 정한다 (`AGENTS.md`). 숫자를 쉬운 말로 바꾸는 것도 코드가 한다.
- 결론 배지에서 "AI 의견"이라는 주어를 지우는 디자인은 하지 않는다. 명령형·권유형 문구(사세요·사 볼 만해요·좋아요)를 쓰지 않는다.
- 개인 맞춤 상담(대화형 질문)은 이번 범위가 아니다.

## 3. 사용자 여정: ① 만들기 → ② 검토 → ③ 실행

```
[홈] 처음이면 3단계 안내 · 최근 AI 리포트 · 만드는 중인 리포트 · 진행 중인 모의 자동매매
   │ 종목 검색 or 최근 리포트
   ▼
① 만들기  [종목 상세] "AI 리포트 만들기" (오늘 이 종목 리포트가 이미 있으면 "리포트 보기"가 먼저)
          ─▶ [리포트] 만드는 중: 쉬운 진행 표시 (조사 → 작성 → 검토). "닫아도 계속 만들어요"
   ▼ (완성 알림: 웹 종 · Discord는 설정한 사람만)
② 검토    [리포트 · 쉬운 보기] AI 의견 배지 · 한 줄 요약 · 신뢰 패널 · 계획 미니 → 쉬운 요약 → 매매 계획(내 계좌로)
          → 근거·위험·의견이 틀리는 경우 → 시나리오 → 차트·재무·뉴스 요약  (용어는 눌러서 풀이, "전문가 보기"로 Agent 그래프·진행 기록)
   ▼ "실행 준비"
③ 실행    [실행 확인] 예산 → 안전장치가 정한 수량과 금액 → 장 시간 안내 → 체크리스트 → "모의 자동매매 시작"
          [모의 자동매매 상세] 단계 표시(주문 → 사는 가격 기다리는 중 → 목표·손절 지켜보는 중 → 팔았어요), 단계마다 알림, 언제든 "멈추기"
```

| 단계 | 사용자가 하는 일 | 완료 기준 |
|---|---|---|
| ① 만들기 | 종목 고르기 → 버튼 하나 | 완성되면 종·리포트 탭 점·(설정했으면) Discord 알림. 실패하면 쉬운 이유와 "다시 만들기" |
| ② 검토 | 결론·계획·근거·위험을 읽고, 모르는 용어를 눌러 본다 | 360×740에서 스크롤 전에 **배지 · 한 줄 요약 · 신뢰 첫 줄 · 계획 미니(손절 시 손실 금액·목표 이익 금액·"실행 준비")**가 보인다 |
| ③ 실행 | 예산을 정하고, 체크리스트를 확인하고 시작 | 시작 뒤 주문·체결·청산이 알림으로 온다. 멈추기 가능 |

**단계 막대의 뜻**: ① 만들기 = 조사·작성 (완성 시 ✓). ② 검토 = AI 검토(완성 시 ✓, 사용자가 할 일 아님) + 읽고 확인하기(완성 화면의 현재 단계).
③ 실행 = 모의 자동매매가 시작되면 ✓. 완성 화면에서는 ②가 현재 단계이고 그 아래에 "결론과 손실 금액을 확인했으면 실행 준비로".

### 4-3. 쉬운 보기 / 전문가 보기 = 주린이모드 켬 / 끔

- **마이 메뉴의 주린이모드 스위치**로 바꾼다. 투자 성향·경험 진단(7문항)이 켬·끔을 추천하고, 진단 전 기본은 켬. 선택은 **계정(서버)에 저장**한다 —
  기기를 바꿔도 같고 웹 알림 문장이 같은 모드를 따르게 (B10, 부록 A2). Discord(팀 공용 채널)는 쉬운 문장 + 숫자 한 줄로 하나만, PDF는 ~~쉬운 요약 상자를 늘 넣는 한 벌~~ 쉬운 판·자세한 판 두 벌 (2026-10-07 바뀜 — `docs/DECISIONS.md` 20장). 화면별 차이는 그 문서 2-3 표.
  **사용성 시험 계정(`시험1~3`)·발표 계정은 시작 전에 주린이모드를 켬으로 되돌린다.** 화면 모드도 확인한다(프로젝터는 밝게 — PC 왼쪽 메뉴 '어두운 모드' 스위치, 2026-10-05). 리포트 상세 위쪽의 "이 화면만 자세히 보기"(저장하지 않음, `?view=expert`)로 발표 중 바로 전환한다.
- 전문가 보기에서만: Agent 그래프·진행 기록(Trace)·Shared State·예시 재생, 장애 주입, 작업 계획·개념 문서, 원래 용어·점수·신뢰도·기대수익률.
  교차검증 분석 요청·상세는 **두 모드 모두에서** 보인다(D-1). 켬에서는 "AI 세 곳이 각자 계획을 내고 서로 검증했어요 · 통과 2 · 최종 승인 ○○" 같은 쉬운 문장과 제안 AI별 카드(사는·목표·손절 가격, 통과/탈락)만, 점수·확률은 끔에서.
- **쉬운 보기에서도 늘 보이는 과제 요소**: 진행 단계(어느 AI가 일하는 중), 자동 복구 문장, 검토 통과와 고쳐 쓴 횟수 — 숨기지 않고 쉬운 말로.
- 쉬운 보기의 "새 계획 제안"·출처 링크는 리포트로만 간다. 분석·연습용 계획은 출처를 늘 표시("AI 교차검증 분석 — 리포트 없음", "연습용 예시 · AI 아님").
- 전문가 보기의 과제 용어도 사용자 용어와 겹치지 않게 바꾼다: "실행 계획" → **"작업 계획(Planner)"**, "실행 과정" → **"진행 기록(Trace)"**.

### 4-5. 매매 계획 카드의 상태 (리포트 상세·실행 확인)

카드는 들어올 때 리스크 미리 보기(예산 없음)를 한 번 불러 상태를 정한다. **"AI 의견: 긍정적"인데 실행할 수 없는 경우를 숨기지 않는다** — 결론과 안전장치가 다른 말을 하면 그 이유를 쉬운 말로 보인다.

| 상태 | 화면 |
|---|---|
| 지켜보기 (hold) | "AI는 지금은 지켜보자는 의견이에요. 실행할 계획이 없어요." + "며칠 뒤 다시 만들기" |
| 부정적 (avoid) | "AI는 위험이 더 크다고 봤어요. 실행할 계획을 만들지 않았어요." (버튼 없음) |
| 긍정적 + 계획 준비 중 (완성 직후) | "실행 계획을 준비하는 중이에요…" — 추천이 생기면 저절로 카드로 바뀐다 |
| 긍정적 + 계획 없음 (가격 조건이 맞지 않음) | "AI가 낸 가격 계획이 맞지 않아(손절 가격이 사는 가격보다 높음 등) 실행 계획을 만들지 않았어요." |
| 기한 지남 | "이 계획은 ○월 ○일에 기한이 끝났어요. 가격이 바뀌었을 수 있으니 새로 만들어 보세요." |
| 실행 가능 | 실제 금액(이 계좌로 ○주 · ○○만 원 · 목표 +○만 / 손절 −○만) + "실행 준비" |
| 실행 불가 | 사유 코드별 문장 (B4): `reward_risk_low` "버는 돈에 비해 잃을 수 있는 돈이 커서 안전장치가 막았어요(손익비 기준 1.5 미만 — 2026-10-07에 2.0에서 바뀜)" · `plan_exists` "이미 이 종목으로 진행 중인 계획이 있어요 → 보기" · `daily_loss_limit` "오늘은 손실 한도에 닿아 새로 시작할 수 없어요. 내일 다시 할 수 있어요" · `price_passed` "지금 가격이 이미 목표 가격을 넘었어요(또는 손절 가격 아래예요)" · `halted` "지금은 새 모의 매수를 멈춰 두었어요" · `budget_too_small` "예산으로는 1주도 살 수 없어요" |

최소 손익비(스윙 1.5, 2026-10-07에 2.0에서 바뀜)는 AI 프롬프트에만 숨기는 값이다. 사용자 화면에는 보여도 된다 (AI가 기준에 맞춰 목표가를 부풀리는 것을 막으려는 규칙이라서).

### 4-6. 기다리는 시간과 장 시간

- 진행 화면의 예상 시간은 **실제 완료 리포트의 `workflow_completed.details.durationMs` 최근 중앙값**("지난 리포트들은 보통 ○분 걸렸어요")으로 보이고, 완료 리포트가 3건 미만이면 시간을 보이지 않는다.
- 만드는 중인 리포트가 있으면 하단 탭 "리포트"에 점(●), 홈에 "만드는 중인 리포트 ○개" 줄.
- 실행 확인과 "사는 가격을 기다리는 중"에 "지금은 장이 닫혀 있어요. ○월 ○일(월) 오전 9시에 주문을 넣어요"(`/api/market`의 `opensAt`). 미국 종목은 "가격은 달러, 이익·손실은 원화(○월 ○일 환율 ○원 기준)".

## 6. 검토 단계 설계 — "AI가 검토하고, 내가 확인한다"

1. **AI 검토 (이미 있는 구조)**: 검토 Agent의 PASS·RETRY·FAIL을 쉬운 문장으로. 예: "검토 AI가 리포트의 주장을 조사 자료와 대조했어요. 근거가 약한 문장 1개를 고쳐 쓰게 했고, 다시 검토해 통과했어요."
   FAIL이면 리포트를 보이지 않고 이유(4-4)와 "다시 만들기". 검토 Agent의 대조 대상에 `plainSummary`도 넣는다 (B1, 담당 2).
2. **리스크 점검 (Handoff)**: 리스크 점검 Agent의 경고가 있으면 결론 위에 노란 상자.
3. **내 확인 (새, 실행 직전)**: 안내 한 줄 "○○원 이하가 될 때까지 ○월 ○일까지만 기다려요. 그때까지 안 내려오면 사지 않고 끝나요(돈은 그대로)" 아래 **체크 셋**을 모두 켜야 시작된다.
   ① "손절 가격(○○원)에 팔리면 약 ○○원을 잃어요. 가격이 갑자기 크게 떨어지면 더 잃을 수도 있어요."
   ② "산 뒤 최대 ○거래일 보유해요. 그때까지 목표·손절에 닿지 않으면 그날 가격에 팔아요 — 이익일 수도, 손실일 수도 있어요."
   ③ "AI의 제안이며 실제 돈이 아닌 모의 투자예요."
   금액은 리스크 미리 보기 값(카드·실행 확인과 같은 값). 서버는 `acknowledged: true`를 `activated` 사건 details에 남긴다 (B5. 서버가 강제하지는 않는다 — 화면 테스트로 보장).

## 7. 실행 단계 변경

- 기능은 그대로(진입 지정가 → 재주문 → 보유 감시 → 청산, 멈추기, 알림). 바뀌는 것은 문구·순서·확인 단계·장 시간 안내.

## 12. 성공 기준과 측정 (수치는 시험한 값만 문서에 쓴다)

- **사용성 시험**: 주식을 거의 해 보지 않은 팀 밖 사람 5명, 과제 넷. **성공 기준은 시험 전에 적어 둔다.**
  ① 아무 국내 종목으로 리포트 만들기 — "만들기를 누르고 진행 화면을 이해했는가"까지(설명하게 한다) ② 미리 만들어 둔 완성 리포트를 보고 "손절에 팔리면 얼마를 잃나"를 말하기 — 화면 값 ±10% 안이면 성공
  ③ 모의 자동매매 시작하기 — 휴장일이라 "사는 가격을 기다리는 중" 상태 확인까지가 성공 ④ "이 리포트가 사라는 말인가요?"를 묻기 — "AI 의견·참고 자료"라고 답하면 성공 (권유 오해 측정). 과제마다 5분 상한.
- **진행 조건**: 시험자마다 따로 시간을 잡는다(동시에 두 명 이상 리포트를 만들지 않는다). 시험 계정 셋(`시험1~3`)을 따로 만들고 시험 뒤 비활성화한다(팀 계정을 주지 않는다 — 랭킹·계좌가 섞인다).
  시험 계정은 투자 성향·경험 진단을 미리 건너뛴 상태(주린이모드 켬)로 준비한다. 하루 리포트 한도와 비용을 시험 전에 확인한다. 기록은 P1~P5 익명으로, 이름·연락처·녹화 파일은 저장소에 넣지 않는다.
  팀 밖 사람에게 배포 URL을 열기 전에 키움 REST API 이용 조건(시세의 제3자 제공)을 확인한다 — 확인 전에는 팀원이 옆에서 진행하는 시험 계정으로만 연다.
- **결과 적기**: "n/5"와 사람별 원표로 적고 백분율·평균으로 일반화하지 않는다. 고친 뒤 다시 재면 처음 보는 사람으로 하거나, 같은 사람이면 그 한계를 적는다.
- 리포트 상세 첫 화면 기준(3장 ②), 쉬운 보기에 용어 사전에 없는 전문 용어가 풀이 없이 나오지 않는다(화면 문구 점검표), 실행은 체크리스트 없이는 시작되지 않는다(화면 테스트), 매매 계획 카드 상태 다섯의 문구(화면 테스트).
- **자동 복구율은 두 가지를 이름으로 나눠 적는다**: ① 시나리오 자동 복구율(평가 가이드 정의, DR 결과표) ② 호출 장애 자동 복구율(Trace 셈법, 관리자 화면의 복구 지표).

### A2. 주린이모드 — 초보와 중급 이상의 화면을 나눈다

본문의 "쉬운 보기 / 전문가 보기"(브라우저 저장 토글)를 **주린이모드**로 바꾼다:
**주린이모드 켬 = 쉬운 보기, 끔 = 일반(중급 이상) 화면.** 켜고 끄는 곳은 **마이 메뉴**이고, 투자 성향·경험 진단이 어느 쪽이 맞는지 추천한다.

#### A2-1. 마이 > 투자 성향·경험 진단 (1분, 7문항)

| # | 질문 | 보기 | 쓰는 곳 |
|---|---|---|---|

| Q2 | 거래해 본 상품 (여럿 고름) | 예적금만 · 펀드·ETF · 국내 주식 · 해외 주식 · 레버리지 ETF·선물·옵션 | 경험 |
| Q3 | 주식 거래 빈도 | 해 본 적 없음 · 1년에 몇 번 · 한 달에 몇 번 · 거의 매일 | 경험 |
| Q4 | "PER, 손절, 지정가"를 남에게 설명할 수 있나요 | 모름 · 들어 봄 · 설명할 수 있음 | 경험 |

- **경험 단계** (Q1~Q4 점수): 입문 · 초급 · 중급 · 숙련.
- **투자 성향 5단계** (Q5~Q7, Q2): 안정형 · 안정추구형 · 위험중립형 · 적극투자형 · 공격투자형 — 증권사 투자성향 분류에서 흔히 쓰는 이름을 빌린다.
  **법정 적합성 진단이 아니다** (모의 투자 연습 도구라서 권유·판매가 없다). 화면에 그렇게 적는다.
- **점수표 (제안값 — E-2에서 바꿀 수 있다)**
  - 경험 점수 = Q1(없음 0 · 1년 미만 1 · 1~3년 2 · 3년 이상 3) + Q3(0 · 1 · 2 · 3) + Q4(모름 0 · 들어 봄 1 · 설명 가능 2) + Q2(국내 주식 1 · 해외 주식 1 · 레버리지 ETF·선물·옵션 2, 합계 최대 3)
    → 0~2 **입문**, 3~5 **초급**, 6~8 **중급**, 9 이상 **숙련**.

    → 0~1 **안정형**, 2~3 **안정추구형**, 4~5 **위험중립형**, 6 **적극투자형**, 7 이상 **공격투자형**.

#### A3-2. 장기투자

**원칙** (조사 보고서 6장): 장기 보유에는 **자동 매도를 붙이지 않는다**. AI 장기 "매수 추천"은 1차에 만들지 않는다 (투자 권유 오해가 가장 큰 영역).
대신 장기 보유자에게 **매일 설명(오늘의 내 종목 뉴스)**과 **분기 점검(펀더멘털 점검)**을 준다.

**(1) 오늘의 내 종목 뉴스** — 매일 장 마감 뒤(16:30 KST, 거래일), 팀원 보유 종목의 합집합을 **종목별로 한 번만** 만든다.

| 단계 | 내용 (결정론 먼저) |
|---|---|
| ① 숫자 분해 | 내 종목 등락 = 시장(코스피 `001`·코스닥 `101` 지수, 키움 `ka20001`/`ka20006`) + 업종(`upName` → `ka10101` → 업종 등락) + **종목 고유 몫**. v1은 β=1로 "시장 대비 초과 등락"이라 부른다. **회계식 분해이지 인과가 아니다** |
| ② 근거 목록 | 그날 DART 공시(사실, 신뢰 높음) · 수급(외국인·기관·개인 순매수 ÷ 거래량) · 증권사 목표가 헤드라인 · 뉴스 제목(신뢰 낮음). 항목마다 ID(`E1`…), 입력 Guard(`guards.clean_text`) 통과 |
| ③ LLM 생략 판단 | 종목 고유 몫이 작고 그날 공시·헤드라인이 없으면 **템플릿 문장**("오늘은 시장·업종과 비슷하게 움직였어요")으로 끝 — LLM 호출 없음 |
| ④ LLM 1회 | 근거 ID 안에서만 설명 (출력 계약 `DailyMoveResult`: headline·summary·drivers[근거 ID]·uncertain). 검사: 근거 ID 존재, 숫자 일치, **인과 단정·권유 표현 금지**("때문에"·"매수 기회" 등), 뉴스 제목뿐이면 uncertain. 위반이면 1번 다시 → 또 위반이면 템플릿 |
| ⑤ 알림 | 사용자당 하루 1개 묶음 (웹 + Discord), 새 kind `daily_move`. 화면 고정 문구: "등락의 원인을 단정하지 않습니다. 같은 날 나온 소식을 모은 것이며 투자 권유가 아닙니다." |

- **리포트 Agent 팀을 쓰지 않고 가벼운 단일 Agent**로 한다 (종목당 0~1회 호출. 리포트 실행기는 동시에 1건이라 수십 종목에 맞지 않는다).
  재시도·대체 모델은 담당 4의 호출기(`healing.LlmCaller`)를 그대로 쓴다 → 장기 기능에도 AutoHealing이 적용된다.
  "이 종목 더 깊게 보기" 버튼이 리포트 만들기(`POST /api/reports`)로 이어진다.
- 종목별 캐시 `DailyMoveNote(symbol, day)` 유일 → 여러 사람이 같은 종목을 가져도 한 번, 엔진 재시작에도 중복 없음. 비용은 `LlmClient.cost`로 기록하고 **첫 주 실측 뒤** 하루 상한을 정한다.

**(2) 펀더멘털 점검** — "산 이유가 아직 맞나"를 **매수 때 값과 비교**한다 (업종마다 정상 범위가 달라 절대 기준은 최소한만).
대상은 **장기 보유 + 국내 일반 기업**만이다 (오늘의 내 종목 뉴스는 스윙을 포함한 모든 보유 종목).

| 지표 | 자료 | ✓ / △ / ✗ (제안값 — 팀이 정한다) |
|---|---|---|
| 매출 성장 | DART 누적·연간, data.go.kr 5년 추이 | ≥0% / −10~0% / <−10% 또는 2번 연속 감소 |

**(3) 장기 보유 방식** — 지금 웹 직접 매수는 목표·손절·기한을 비우면 이미 자동 청산 없이 보유된다. 이것을 "장기 보유"로 이름 붙이고(1차는 표시만, 나중에 `PaperOrder.style = long`),

분봉 조회는 키움 국내 조회 초당 5회 예산을 나눠 쓰므로 **종목당 1분 캐시**를 둔다.

**AI의 역할 — 틱 판단에 LLM을 쓰지 않는다** (리포트 한 건에 수 분, 종목당 비용, AI는 제안만 규칙):

| 시간 | 누가 | 무엇을 |
|---|---|---|
| 장 전 08:00~09:00 | AI (`day_plan` 팀) | 관심 종목 5~10개와 종목별 당일 계획: 진입 가격대·조건(예: 전일 고가 돌파), 무효화 가격, 목표 구간, "오늘 하지 말 것". 지금 리포트 → 매매 계획 흐름을 "당일 계획"으로 쓴다 |
| 장 전 | 리스크 엔진 | 계획마다 수량, 하루 최대 손실, 하루 최대 거래 수 확정 |
| 장중 | 결정론 규칙 + 분봉(나중에 틱) 체결기 | 조건 충족 시 모의 주문, 손절·목표·**장 마감 전 강제 청산**. AI 호출 없음 |
| 장 후 | AI (`day_review` 팀) | 복기: 계획 대비 실제 체결, 규칙 위반·놓친 기회, **비용(수수료·거래세) 영향**, 다음 날 계획 수정 제안. 체결·손익 사실은 DB 값 그대로 |

**(b)를 붙일 때의 구조** (조사 보고서 3장, 요약): 별도 `ticker` 프로세스(백엔드 관리 명령 — 엔진은 표준 라이브러리만이라 WebSocket 패키지는 `backend/`에) → Redis(`paper:tick:*`, `paper:ticks:*` 스트림, `paper:rt:want` 구독 우선순위) →
`run_engine`의 틱 체결기(**DB에 주문을 쓰는 프로세스는 계속 `run_engine` 하나**). 키움은 토큰별 세션이 1개라 **실시간 세션은 한 서버의 한 프로세스만** 연다 (엔진 CLI 등 다른 프로세스는 열지 않는다). 구독 우선순위: 진행 중 단타 주문·보유 > 활성 계획 > 화면에서 보는 종목 > 장 전 관심 종목.
자리가 모자라면 REST 폴링으로 — **실시간은 추가 경로이고 폴링이 늘 대체 경로**다. 끊김·조용한 끊김·토큰 무효·등록 거절은 AutoHealing 틀(감지 → 재접속 → 대체 경로 → 알림, 장애 주입·지표)에 새 장애 유형(DR-FEED-01~03)으로 넣는다.
틱 체결 규칙은 지금보다 보수적으로: 지정가는 체결가가 지정가를 **뚫고 지나가야** 체결, 끊긴 구간은 메우지 못하면 체결하지 않는다, VI·동시호가 구간은 대기, 비용 합계 표시.

**단타 리스크·안전**: 주린이모드 끔 + 연습 퀴즈 통과 뒤에만 연다. 하루 최대 손실·거래 수에 닿으면 그날 새 진입을 막는다. 화면·알림에 "단타는 비용이 손익을 크게 좌우해요"와 비용 합계를 늘 보인다. 그 전에 엔진의 국내 매도 거래세율(0.2%)이 지금 세율과 맞는지 확인한다.

| 항목 | 조사 결과 |

### B-3. 넣을 기능

#### 우선

**① 내 투자 성적표**
- 무엇: 마이 '내 성적' 카드에 누적·일간 수익률 추이, 최대 낙폭(MDD), 승률, 평균 이익 ÷ 평균 손실(화면 이름 "벌 때와 잃을 때"), 평균 보유 기간, 현금비중을 더한다. 승률 옆에 "승률이 높아도 손해일 수 있어요"를 붙인다. 닫은 거래가 5건 미만이면 승률 대신 "거래가 더 쌓이면 보여요"를 보인다.
- 초보자에게 왜: 수익률 하나로는 운인지 습관인지 모른다. 크게 잃은 적이 있는지(MDD), 작게 벌고 크게 잃는지(평균 이익 ÷ 평균 손실)를 같이 봐야 고칠 점이 보인다.
- 데이터: **이미 있는 데이터**. `EquityDaily`(하루 1번 총자산), `PaperAccount.initial_capital_krw`(첫 고점), `PaperOrder`(CLOSED·`pnl_krw`·`filled_at`·`closed_at`), 계좌 요약. 새 조회 없음.
- 담당 위치: 계산은 엔진 순수 함수(새 모듈 `engine/paper_engine/records/performance.py`, 표준 라이브러리) → 백엔드 `backend/trading/service.py`(`equity_points` 옆)의 새 읽기 API(`docs/API.md` 먼저) → 프론트 `frontend/src/components/my/PerformanceCard.tsx`.
- 지킬 규칙: 장마감 기준(`docs/DECISIONS.md` 14-1). 계획의 "손익비"와 이름을 나눈다(B-4). 권유·예측 문구 금지(`engine/paper_engine/wording.py`). Sharpe·Sortino는 넣지 않는다(B-5).

**② 시장과 겨루기 (코스피 대비 수익률)**
- 무엇: 성적표 그래프에 같은 기간 시장 등락선을 겹치고 "시장보다 +x%p"를 보인다.
- 초보자에게 왜: 시장이 다 같이 올라서 번 것인지 내 판단으로 번 것인지 가르는 가장 쉬운 기준이다. 키움 대학생 대회도 시장수익률보다 낮으면 시상에서 뺀다.
- 데이터: **이미 받는 데이터** — 장기투자와 같은 KODEX 200(`069500`)·KODEX 코스닥150(`229200`) 대용, 화면에 "KODEX 200 기준"이라고 적는다. 화면 일봉은 120봉만 캐시하므로 `backend/trading/service.py` `record_equity` 때 대용 ETF 종가를 같이 남긴다(`EquityDaily` 열 추가 또는 새 표 — 기간 제한이 없고, 호출은 하루에 ETF 종가 1~2번만 는다). 진짜 지수는 **새 읽기 전용 조회**(토스 `/api/v1/market-indicators/{symbol}/candles`, 키움 `ka20006` 실측 전)라 U30 결정 뒤.
- 담당 위치: 엔진 ①과 같은 모듈, 백엔드 `backend/trading/models.py` `EquityDaily`(마이그레이션)·`record_equity`·①의 API, 프론트 성적표와 `frontend/src/pages/RankingPage.tsx`.
- 지킬 규칙: 새 조회 메서드는 `KiwoomClient`·`TossClient` 둘 다 같은 이름·반환으로 둔다(`data/broker.make_client`). 키움 쪽이 없으면 `None`을 돌려주고 화면은 대용으로 견딘다. 지수를 붙이면 `docs/DECISIONS.md` 14-3의 "토스 조회에는 지수가 없고"를 지금 명세에 맞게 고친다.

**③ 실현손익 일지와 매매 이유 한 줄**
- 무엇: 날짜별·종목별 실현손익(수수료·세금 포함) 목록, 매수마다 "왜 샀나요?" 한 줄(주린이모드는 고르는 칩: 리포트를 보고 · AI 계획 · 뉴스 · 차트 · 그냥). 성적표를 **AI 계획 주문 / 내 직접 주문**으로 나눠 본다.
- 초보자에게 왜: 무엇 때문에 샀을 때 잘됐는지 돌아볼 수 있다. AI 계획과 내 판단의 성과를 나란히 보면 AI를 맹신하지도 무시하지도 않게 된다.
- 데이터: **이미 있는 데이터**. `PaperOrder.pnl_krw`, `PaperFill.commission`·`tax`. 계획 주문 구분은 `PaperOrder.requested_by`가 `plan:`으로 시작하는지로 한다(`backend/autotrade/plans/executor.py` `requester` — 새 열 없음, `TradePlan.order`는 재주문하면 바뀌어 쓰지 않는다). 이유 한 줄만 새 열이다(`PaperOrder.note`는 취소·청산 사유로 이미 쓰므로 따로, null 허용). 장기 보유는 기존 `InvestmentThesis`를 그대로 쓴다.
- 담당 위치: 백엔드 `backend/trading/models.py`(새 열·마이그레이션)·`service.py` `buy`, 집계는 `GET /api/fills` 확장 또는 새 API(`docs/API.md` 먼저), 프론트 `frontend/src/pages/PortfolioPage.tsx`·`frontend/src/components/stock/OrderPanel.tsx`.
- 지킬 규칙: 메모는 주문을 막지 않는다(필수로 할지는 U31). 메모는 사용자 자유 문장이라 AI 프롬프트 입력으로 쓰지 않는다. SQLite·PostgreSQL 둘 다 되는 열만.

**④ 매매 제한 종목 점검을 직접 주문에도**
- 무엇: 정리매매·투자경고·투자위험·관리종목·거래정지 종목의 **새 매수**를 직접 주문과 정규장 밖 예약 매수에서도 막는다(지금은 자동매매 계획만 막는다). 투자주의·단기과열은 확인 한 번을 받고 진행한다(제안). VI(`VI_*`)·`STOCK_WARRANTS`는 막지 않는다(VI는 장중 상태인데 `warnings`는 하루 캐시다).
- 초보자에게 왜: 키움·대신 상시 모의투자와 한투 대회가 막는 종목이다. 초보자가 급등한 위험 종목에 몰리는 것을 막는다.
- 데이터: **이미 받는 데이터**. 토스 `warnings`(정리매매·과열·투자경고·투자위험)와 `stocks`의 `koreanMarketDetail`(거래정지·정리매매). 관리종목·투자주의는 키움 변환에서만 나오므로 토스 운영 중에는 "판정 불가"로 표시한다.
- 담당 위치: 막는 자리는 엔진 `engine/paper_engine/agents/executor.py` `PaperExecutor.buy_checks`(직접·예약·계획 매수가 모두 거친다). 지정 목록은 부르는 쪽(`backend/trading/service.py` `buy`·`execute_reservation`)이 `backend/trading/market.py` `warnings`에서 받아 넘긴다. 유형 분류는 `backend/reports/agents/report_team/risk.py` `HIGH_WARNING_TYPES`를 한 곳으로 옮겨 같이 쓴다. 키움 변환 `ORDER_WARNINGS`(`engine/paper_engine/data/kiwoom.py`)의 `SHORT_TERM_OVERHEATED`를 토스 이름 `OVERHEATED`로 맞추고 `market.WARNING_LABELS`도 고친다. 사유 코드는 이미 있는 `warning_stock`(`docs/API.md` 실행 불가 사유 코드 표)을 다시 쓴다.
- 지킬 규칙: 판정은 코드. 매도·청산은 막지 않는다. 사유 문장에 장중 가격 숫자를 넣지 않는다(14-1). 범위와 1,000원 미만 종목은 U29.

- **⑤ 랭킹 보강** — 무엇: 순위 변동(▲▼·NEW), 자격(시즌 안에 거래한 날 3일·종목 2개 이상 — 제안값), 동률 규칙을 지금의 닉네임순에서 거래금액 → 거래일수로, "시장 대비"·"MDD 작은 순" 탭(MDD 탭은 자격을 채운 사람만 — 거래가 없는 계좌가 MDD 0으로 1위가 되지 않게). 시즌·자격은 U32, 공개 범위를 넓히는 것은 U33. 데이터: 이미 있음(`EquityDaily`·`PaperFill`, `backend/trading/service.py` `ranking`). 순위 변동은 전날 순위를 남겨야 한다.

- **⑦ 체결가 보수화** — 무엇: 모의 체결가를 매수는 최우선 매도호가, 매도는 최우선 매수호가 쪽으로 잡는다(지금은 현재가·두 호가의 중간값). U35 결정 뒤. 데이터: 이미 받는 `orderbook`. 방향별 확인 가격은 새 메서드로 두 클라이언트에 같게 만든다(`TossClient`가 `engine/paper_engine/data/kiwoom.py` `confirmed_prices` 구현을 같이 쓴다). 키움 `_levels`의 `quantity`는 토스 형식 `volume`으로 맞춘다.
- **⑧ 종목 화면 지표 (전문가 보기)** — 무엇: MACD·볼린저·RSI를 차트 아래에서 고르고, 52주 최고·최저와 지금 위치를 보인다(주린이모드는 52주 위치만 쉬운 말로). 데이터: 보조지표는 이미 받는 일봉(화면 120봉). RSI는 엔진에 마지막 값만 있어 차트용 연속 값은 새로 계산한다. 52주는 종목당 하루 1번 `candles_before` 2쪽(200 + 50 — 토스는 한 번에 최대 200봉)을 따로 캐시한다(`CANDLE_COUNT`는 올리지 않는다). 계산은 `frontend/src/lib/`에 함수로 빼고 지금 `CandleChart.tsx` 안 `movingAverage`도 같이 옮긴다. 시가총액은 뺀다(토스 `sharesOutstanding`은 있지만 키움 `_kr_stock`에 없어 반환 형식이 다르고, DART `parse_shares`는 유통주식수다).

### B-5. 넣지 않는 것

- 신용·미수·공매도·증거금·3일 결제: 초보자 컨셉과 맞지 않고, 현금 즉시 정산 계좌 구조를 바꿔야 한다.
- 선물·옵션·파생 모의거래 이수: 선물 폐기(`docs/DECISIONS.md` 13-2 E-7). 우리 모의거래는 법정 모의거래로 인정되지 않는다(`docs/research/조사.md` D장).
- 단타·분봉·체결강도: 단타 폐기(16장). 체결강도는 토스 `trades`에 매수·매도 구분이 없다.
- 실제 주문·계좌 API: 실주문 코드 0건. 토스 명세에 주문·계좌 경로가 같이 있어도 쓰지 않는다.
- 체결량 기반 부분 체결·상한가 0.1 배분: 같은 종목 포지션 하나·매도는 전량(4-2)과 맞지 않는다. 대신 ⑦로 체결가를 보수적으로 잡는다.
- 최유리·최우선 지정가, IOC·FOK, GTC, 시간외: 초보자에게 필요성이 낮고 정규장 체결 규칙을 넓혀야 한다.
- 투자원금 고르기: 팀 랭킹은 같은 출발점(1천만원)일 때 공정하다.
- 남의 보유 종목 보기·따라 하기: 공개 범위(닉네임·수익률)와 "넣을 돈은 사용자가 정한다"(28장)에 부딪힌다.
- 상금·대회 운영: 팀 내부 교육 서비스 범위 밖이다.
- Sharpe·Sortino: 5명·짧은 기간에서는 값이 크게 흔들려 초보자에게 오해를 준다 (제안).
- 배당·권리락 보정, 미국 주식 지표: 배당 조회 항목명을 확인하지 못했고, 운영은 `MARKETS=KR`이다.

### B-6. 결정할 것

`docs/plans/TEAM_PAPER_TRADING_PLAN.md` 4-1 표에 올렸다. 결정하면 그 표의 상태를 고치고 결과를 이 부록과 `docs/DECISIONS.md`에 옮긴다.

- **U29** 직접 주문에서 막을 유의 종목 범위와 1,000원 미만 종목 (④) — 제안: 정리매매·경고·위험·관리·거래정지는 막고, 주의·과열은 확인 후 진행, 1,000원 미만은 표시만.
- **U30** 시장 대비 수익률의 시장 값 (②) — 제안: KODEX 대용으로 시작하고, 키움 `ka20006` 실측 뒤 두 클라이언트 모두 지수로.
- **U31** 매매 이유 한 줄을 필수로 받을지 (③) — 제안: 선택, 주린이모드는 칩으로 한 번 묻기.
- **U32** 랭킹 시즌·자격·동률 규칙 (⑤) — 제안: 한 달 시즌, 거래한 날 3일·종목 2개 이상, 동률은 거래금액 → 거래일수.
- **U33** 랭킹 공개 범위를 MDD·시장 대비·거래일수까지 넓힐지 (⑤) — 제안: 지표만 넓히고 금액·보유 종목은 계속 비공개.
- **U34** 트레일링 스톱의 화면 표시 (⑥) — 제안: 올라간 손절가 숫자 대신 규칙("고점 대비 −x%")만 보인다(14-1).
- **U35** 체결가 보수화와 수수료 (⑦) — 제안: 체결가를 보수화하고 수수료는 실제와 같게 0.015% 유지. 방향별 가격을 청산 판단에도 쓸지 같이 정한다.
- **U36** 계좌 리셋을 범위 밖에서 꺼낼지 — 제안: 넣는다면 시즌이 바뀔 때만, 기록은 지우지 않고 회차로 닫는다.
