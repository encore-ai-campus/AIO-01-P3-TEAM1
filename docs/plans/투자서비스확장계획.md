## 2. 주린이모드 — 초보와 중급 이상의 화면을 나눈다

`docs/plans/컨셉변경계획.md`의 "쉬운 보기 / 전문가 보기"(브라우저 저장 토글)를 **주린이모드**로 바꾼다:
**주린이모드 켬 = 쉬운 보기, 끔 = 일반(중급 이상) 화면.** 켜고 끄는 곳은 **마이 메뉴**이고, 투자 성향·경험 진단이 어느 쪽이 맞는지 추천한다.

### 2-1. 마이 > 투자 성향·경험 진단 (1분, 7문항)

| # | 질문 | 보기 | 쓰는 곳 |
|---|---|---|---|
| Q1 | 주식 투자를 해 본 기간 | 없음 · 1년 미만 · 1~3년 · 3년 이상 | 경험 |
| Q2 | 거래해 본 상품 (여럿 고름) | 예적금만 · 펀드·ETF · 국내 주식 · 해외 주식 · 레버리지 ETF·선물·옵션 | 경험 |
| Q3 | 주식 거래 빈도 | 해 본 적 없음 · 1년에 몇 번 · 한 달에 몇 번 · 거의 매일 | 경험 |
| Q4 | "PER, 손절, 지정가"를 남에게 설명할 수 있나요 | 모름 · 들어 봄 · 설명할 수 있음 | 경험 |
| Q5 | 1,000만 원을 넣었다면 견딜 수 있는 손실 | 원금 손실은 싫다 · −10%까지 · −20%까지 · 그 이상도 괜찮다 | 성향 |
| Q6 | 주로 생각하는 투자 기간 | 몇 년 이상 · 몇 주 · 하루 안 | 성향·추천 서비스 |
| Q7 | 투자 목적 | 연습·공부 · 꾸준한 자산 증식 · 짧은 기간 수익 | 성향 |

- **경험 단계** (Q1~Q4 점수): 입문 · 초급 · 중급 · 숙련.
- **투자 성향 5단계** (Q5~Q7, Q2): 안정형 · 안정추구형 · 위험중립형 · 적극투자형 · 공격투자형 — 증권사 투자성향 분류에서 흔히 쓰는 이름을 빌린다.
  **법정 적합성 진단이 아니다** (모의 투자 연습 도구라서 권유·판매가 없다). 화면에 그렇게 적는다.
- **점수표 (제안값 — E-2에서 바꿀 수 있다)**
  - 경험 점수 = Q1(없음 0 · 1년 미만 1 · 1~3년 2 · 3년 이상 3) + Q3(0 · 1 · 2 · 3) + Q4(모름 0 · 들어 봄 1 · 설명 가능 2) + Q2(국내 주식 1 · 해외 주식 1 · 레버리지 ETF·선물·옵션 2, 합계 최대 3)
    → 0~2 **입문**, 3~5 **초급**, 6~8 **중급**, 9 이상 **숙련**.
  - 성향 점수 = Q5(0 · 1 · 2 · 3) + Q6(몇 년 이상 0 · 몇 주 1 · 하루 안 2) + Q7(연습·공부 0 · 꾸준한 증식 1 · 짧은 기간 수익 2) + Q2 파생 경험(있으면 1)
    → 0~1 **안정형**, 2~3 **안정추구형**, 4~5 **위험중립형**, 6 **적극투자형**, 7 이상 **공격투자형**.
- 처음 로그인하면 진단을 권한다(건너뛸 수 있음). 진단 전 기본값은 **주린이모드 켬**.
- 점수 계산은 **결정론적 코드**(LLM 아님)이고, 문항·점수표는 문서와 코드에 같이 둔다.

### 2-2. 추천과 전환

| 경험 단계 | 추천 | 사용자가 바꿀 수 있나 |
|---|---|---|
| 입문 · 초급 | 주린이모드 **켬** | 언제든 끌 수 있다 (끌 때 "어려운 용어·숫자가 그대로 나와요" 한 줄 확인) |
| 중급 · 숙련 | 주린이모드 **끔** | 언제든 켤 수 있다 |

- 마이 메뉴 맨 위에 **주린이모드 스위치**와 "진단 결과: 초급 · 위험중립형 → 주린이모드 켬 추천"을 보인다. 다시 진단할 수 있다.
- 모드는 **계정(서버)에 저장**한다 — 기기를 바꿔도 같고, **웹 알림 문장**이 같은 모드를 따른다 (컨셉 계획 13장 D-3 "브라우저 저장"을 이것으로 바꾼다).
  Discord는 팀 공용 Webhook 채널 하나라 받는 사람마다 다른 문장을 보낼 수 없다 → **쉬운 문장 + 숫자 한 줄로 하나만** 보낸다. ~~PDF는 리포트당 파일 하나라 **쉬운 요약 상자를 늘 넣는 한 벌**로 둔다.~~ → 2026-10-07 바뀜(`docs/DECISIONS.md` 20장): PDF도 **쉬운 판·자세한 판 두 벌** — 주린이모드(또는 화면의 `?view`)를 따르고, Discord 자동 리포트는 쉬운 판.
- 리포트 상세 위쪽에 **"이 화면만 자세히 보기" 토글**(저장하지 않음, 주소 `?view=expert`)을 남긴다 — 계정의 주린이모드는 바꾸지 않고 그 화면만 끔 모드로 보인다.
- 발표: 쉬운 화면(켬)으로 시작 → 리포트 상세의 "이 화면만 자세히 보기"로 같은 리포트의 Agent 진행 기록을 보인다 (컨셉 계획 11장의 "전문가 보기 전환". 마이까지 가지 않아 시연 흐름이 끊기지 않는다).

### 2-3. 모드별 화면

**발표 전(0단계)에 만드는 것은 리포트·용어·실행 확인·직접 주문·알림 행과 홈의 켬 쪽(3단계 안내·최근 리포트·진행 중)뿐이다.** "(1단계)"·"(2단계)"·"(3단계)"가 붙은 것은 해당 단계에서 붙이고, 그 전에는 화면에 나오지 않는다 (5장 로드맵).

| 영역 | 주린이모드 켬 (입문·초급) | 끔 (중급 이상) |
|---|---|---|
| 홈 | 3단계 안내(만들기 → 검토 → 실행), 최근 리포트, 진행 중 모의 자동매매, 오늘의 내 종목 뉴스 쉬운 요약(1단계) | 관심 종목 시세, 진행 중 계획·주문, 최근 리포트, 시장 요약(지수·업종 등락, 1단계) |
| 메뉴 | 홈 · 종목 · 리포트 · 모의투자 · 마이 | 같음 + 투자 방식 전환(장기·스윙. 처음엔 단타 연습장도 있었으나 2026-10-06 폐기) |
| 종목 상세 | 선 차트 + 큰 버튼 "AI 리포트 만들기", 펀더멘털 신호등(1단계) | 캔들·이동평균·거래량, 직접 주문(지정가·예약), 펀더멘털 지표 표·추이(1단계) (분봉은 단타와 함께 2026-10-06 폐기) |
| 리포트 | 쉬운 보기: AI 의견 배지·쉬운 요약·신뢰 패널·"이 계좌로는" 금액·매매 계획 카드 상태 (컨셉 계획 4~5장) | 지표 전부·확률·기대수익률·검토 점수·**진행 기록(Agent 그래프·Trace)** 탭 |
| 용어 | 쉬운 말 + 용어 사전 | 원래 용어 (용어 사전은 눌러서) |
| 실행 확인 | 체크리스트 셋을 하나씩 확인(갭 손실·기한 매도·모의/AI 제안), 예산 입력 권유 | **같은 체크리스트 셋을 한 화면에 요약해 한 번에 확인** (갭 손실·기한 매도는 숙련자에게도 같은 사실. `acknowledged: true`도 같다), 예산 자유 |
| 직접 주문 | "고급"으로 접어 둠 | 바로 보임 |
| 오늘의 내 종목 뉴스 (1단계) | 세 숫자(시장·업종·내 종목) + 쉬운 문장 3줄 | 등락 분해 수치·수급 비율·근거 목록(공시·뉴스·헤드라인) |
| 펀더멘털 점검 (1단계) | 신호등(견조·주의·점검 필요) + 한 줄 | 지표 표(값·매수 때 기준선·✓△✗)·5년 추이 |
| ~~단타 (2단계)~~ **폐기 (2026-10-06)** | ~~**잠금**: "주린이모드를 끄고 연습 퀴즈를 통과하면 열려요"~~ | ~~연습 퀴즈(5문항: 당일 청산·손절·비용·VI·모의) 통과 뒤 열림~~ |
| 알림 | 쉬운 문장과 이유 ("손실이 더 커지지 않게 팔았어요") | 짧은 숫자 위주 ("삼성전자 −3.0% 손절 체결 67,700") |

성향은 화면만 바꾸고 **리스크 엔진의 수량 계산은 바꾸지 않는다** (컨셉 계획 13장 D-6 유지). 대신 성향과 맞지 않는 서비스를 고르면 안내를 한 줄 보인다
(예였던 "안정형이 단타를 열면 …"는 2026-10-06 단타 폐기로 없다).

### 3-2. 장기투자

**원칙** (조사 보고서 6장): 장기 보유에는 **자동 매도를 붙이지 않는다**. AI 장기 "매수 추천"은 1차에 만들지 않는다 (투자 권유 오해가 가장 큰 영역).
대신 장기 보유자에게 **매일 설명(오늘의 내 종목 뉴스)**과 **분기 점검(펀더멘털 점검)**을 준다.

**(1) 오늘의 내 종목 뉴스** — 매일 장 마감 뒤(16:30 KST, 거래일), 팀원 보유 종목의 합집합을 **종목별로 한 번만** 만든다.

| 단계 | 내용 (결정론 먼저) |
|---|---|
| ① 숫자 분해 | 내 종목 등락 = 시장(코스피 `001`·코스닥 `101` 지수, 키움 `ka20001`/`ka20006`) + 업종(`upName` → `ka10101` → 업종 등락) + **종목 고유 몫**. v1은 β=1로 "시장 대비 초과 등락"이라 부른다. **회계식 분해이지 인과가 아니다** |
| ② 근거 목록 | 그날 DART 공시(사실, 신뢰 높음) · 수급(외국인·기관·개인 순매수 ÷ 거래량) · 증권사 목표가 헤드라인 · 뉴스 제목(신뢰 낮음). 항목마다 ID(`E1`…), 입력 Guard(`guards.clean_text`) 통과 |
| ③ LLM 생략 판단 | 종목 고유 몫이 작고 그날 공시·헤드라인이 없으면 **템플릿 문장**("오늘은 시장·업종과 비슷하게 움직였어요")으로 끝 — LLM 호출 없음 |
| ④ LLM 1회 | 근거 ID 안에서만 설명 (출력 계약 `DailyMoveResult`: headline·summary·drivers[근거 ID]·uncertain). 검사: 근거 ID 존재, 숫자 일치, **인과 단정·권유 표현 금지**("때문에"·"매수 기회" 등), 뉴스 제목뿐이면 uncertain. 위반이면 1번 다시 → 또 위반이면 템플릿 |
| ⑤ 알림 | 사용자당 하루 1개 묶음 (웹 + Discord), 새 kind `daily_move`. 화면 고정 문구: "등락의 원인을 단정하지 않습니다. 같은 날 나온 소식을 모은 것이며 투자 권유가 아닙니다." |

- **리포트 Agent 팀을 쓰지 않고 가벼운 단일 Agent**로 한다 (종목당 0~1회 호출. 리포트 실행기는 동시에 1건이라 수십 종목에 맞지 않는다).
  재시도·대체 모델은 담당 4의 호출기(`healing.LlmCaller`)를 그대로 쓴다 → 장기 기능에도 AutoHealing이 적용된다.
  "이 종목 더 깊게 보기" 버튼이 리포트 만들기(`POST /api/reports`)로 이어진다.
- 종목별 캐시 `DailyMoveNote(symbol, day)` 유일 → 여러 사람이 같은 종목을 가져도 한 번, 엔진 재시작에도 중복 없음. 비용은 `LlmClient.cost`로 기록하고 **첫 주 실측 뒤** 하루 상한을 정한다.

**(2) 펀더멘털 점검** — "산 이유가 아직 맞나"를 **매수 때 값과 비교**한다 (업종마다 정상 범위가 달라 절대 기준은 최소한만).
대상은 **장기 보유 + 국내 일반 기업**만이다 (오늘의 내 종목 뉴스는 스윙을 포함한 모든 보유 종목).

| 지표 | 자료 | ✓ / △ / ✗ (제안값 — 팀이 정한다) |
|---|---|---|
| 매출 성장 | DART 누적·연간, data.go.kr 5년 추이 | ≥0% / −10~0% / <−10% 또는 2번 연속 감소 |
| 영업이익 성장 | DART | ≥0% / −20~0% / <−20% 또는 적자 전환 |
| 영업이익률(TTM) | DART | 매수 때 대비 −1%p 이내 / −1~−3%p / −3%p 넘게 또는 음수 |
| ROE | DART 공시 지표 (2023년 3분기 이후 제공) | 기준선 −2%p 이내이고 >0 / 더 하락 / ≤0 |
| 부채비율 | DART + 5년 추이 (금융업 제외) | +20%p 이내 / +20~+50%p / +50%p 넘게 |
| 유동비율 | DART (보조) | ≥100% / 80~100% / <80% |
| 이자보상배율 | 영업이익 ÷ 금융비용 (근사 — 정확한 이자비용은 확인 필요) | ≥3 / 1~3 / <1 (3년 연속이면 "한계기업 기준 해당") |
| 영업현금흐름 | DART 전체 재무제표의 현금흐름표 — **이미 받는 응답에서 파싱만 더하면 된다** | >0이고 순이익과 같은 부호 / 흑자인데 OCF 적자 1회 / 2회 연속 |
| 이익의 질 | 순이익÷영업이익, 영업외 손익 비중 (DART) | – / 영업외 비중이 커서 순이익이 영업이익과 크게 다름 / – (경고만) |
| 목표가 방향 (보조) | 증권사 헤드라인 최근 30일 하향 건수 (제목 파싱 자료) | – / 하향 2건 이상 / – (✗로 쓰지 않음) |

- 종합: ✗ 하나라도 → "점검 필요", △ 둘 이상 → "주의", 나머지 → "견조". 금융업·ETF·리츠는 "일반 기업용 점검이라 적용하지 않음".
- **산 이유(투자 논리) 저장**: 매수 때 `InvestmentThesis`(이유 셋, 점검할 축, 매수 때 지표 기준선)를 남긴다 — 리포트·추천에서 샀으면 그 근거로, 직접 샀으면 "왜 샀나요?" 체크박스로.
- **언제**: 매일 18:00 새 정기공시 감지(DART 공시 검색 `pblntf_ty=A`, 하루치 일괄) + 주 1회 재점검. 정기보고서 제출 기한(사업보고서 90일, 반기·분기 45일) 때문에 3·5·8·11월에 몰린다.
- **알림**: 새 kind `thesis_check`. ✗가 새로 생기거나 종합이 나빠졌을 때만 Discord까지. **매도 권유 문구를 넣지 않고 자동 매도도 하지 않는다** ("점검 필요 항목이 생겼어요" + 지표 표).

**(3) 장기 보유 방식** — 지금 웹 직접 매수는 목표·손절·기한을 비우면 이미 자동 청산 없이 보유된다. 이것을 "장기 보유"로 이름 붙이고(1차는 표시만, 나중에 `PaperOrder.style = long`),
장기 매수 미리 보기는 손절 기반 수량 대신 **비중 한도**(`RiskLimits.max_position`)만 본다 — **100%로 정했다**(E-4, 2026-10-04): 한 종목에 계좌 전부까지 살 수 있고 실제 한도는 현금이다.

### 3-3. 스윙 (지금 워크플로우, 기준선)

지금 그대로다: AI 리포트(멀티 Agent `stock_report`) → AI 의견·매매 계획 → 리스크 엔진 → 모의 자동매매(진입 지정가·재주문·목표·손절·기한) → 알림.
바뀌는 것은 이름(`style: swing`, 화면 "스윙 리포트")과 방식 전환 화면에서의 위치뿐이다. 장기가 이 구조(리포트 → 계획 → 실행 → 알림)를 재사용한다 (처음엔 단타도 재사용하기로 했으나 폐기).

자리가 모자라면 REST 폴링으로 — **실시간은 추가 경로이고 폴링이 늘 대체 경로**다. 끊김·조용한 끊김·토큰 무효·등록 거절은 AutoHealing 틀(감지 → 재접속 → 대체 경로 → 알림, 장애 주입·지표)에 새 장애 유형(DR-FEED-01~03)으로 넣는다.
틱 체결 규칙은 지금보다 보수적으로: 지정가는 체결가가 지정가를 **뚫고 지나가야** 체결, 끊긴 구간은 메우지 못하면 체결하지 않는다, VI·동시호가 구간은 대기, 비용 합계 표시.

**단타 리스크·안전**: 주린이모드 끔 + 연습 퀴즈 통과 뒤에만 연다. 하루 최대 손실·거래 수에 닿으면 그날 새 진입을 막는다. 화면·알림에 "단타는 비용이 손익을 크게 좌우해요"와 비용 합계를 늘 보인다. 그 전에 엔진의 국내 매도 거래세율(0.2%)이 지금 세율과 맞는지 확인한다.
