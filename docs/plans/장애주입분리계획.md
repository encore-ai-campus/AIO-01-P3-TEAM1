## 2. 나눈 뒤 모습

- 장애 주입을 **켜고 신청하는 곳은 관리 서버 하나**다. 서비스 화면과 서비스 공개 API에는 장애 주입이 없다 — 켜는 것도, 보이는 것도.
- 장애 주입 실행의 진행·실행 기록·복구는 관리 서버에서 본다.
- **주입 지점은 서비스에 남는다.** AI 호출이 서비스 엔진(`run_engine`)에서 돌기 때문에 `healing`의 실제 호출 직전 한 곳(`chaos.should_fail`)과 리포트 전용 Breaker는 그대로다.
  관리 서버로 옮기는 것은 "켜는 길"과 "보는 곳"이다. 복구 경로·Trace 형식·복구 셈법(`admin/recovery_cases.json`)은 바뀌지 않는다.
- 관리 서버의 서비스 DB 권한은 그대로 읽기 전용이다. 쓰기는 서비스의 내부 API 하나로만 한다.

```
관리자 화면 /chaos ─ POST /api/admin/chaos/runs (세션 쿠키만) ─▶ 관리자 백엔드
  ─▶ tunnel 컨테이너 (지금 DB 터널에 포워딩 하나 더) ─SSH─▶ 서비스 서버 127.0.0.1:18000 (web)
       POST /api/internal/chaos-runs (서명) ─▶ Report(source="chaos", user=None, chaos=…) → 서비스 엔진이 실행
관리자 화면 /reports/:id ◀─ 읽기 전용 DB (지금과 같다)
```

켜는 길을 고른 이유:

| 방법 | 판단 |
|---|---|
| **A. 서비스 내부 API + SSH 터널 + 서명 (권장)** | DB 권한이 그대로다. 관리 서버 ↔ 서비스 사이에 HTTPS가 없는데 요청이 인터넷에 평문으로 나가지 않는다. 실행을 만드는 규칙(종목 확인·`chaos.parse`·예산)이 서비스 한 곳에 남는다 |
| B. 서비스 공개 주소로 부름 (서명만) | 터널을 고치지 않아도 되지만 요청이 평문으로 인터넷을 지나고, 내부 경로를 공개 nginx에 열어야 한다 |
| C. 관리 서버가 DB에 실행 요청 행을 씀 | 읽기 전용 계정 원칙(`admin-ci.yml` schema 작업이 쓰기 실패를 확인)을 깬다. 종목 확인·seed·예산을 관리 서버가 다시 만들어야 한다 — 하지 않는다 |

## 3. 서비스 화면 (`frontend/`) — 지운다

## 4. 서비스 API·백엔드 (`docs/API.md`를 먼저 고친다)

### 4-1. 공개 API

- `POST /api/reports`: `chaos`를 받지 않는다. 들어 있으면 `400 "장애 주입은 관리 서버에서만 켭니다."` (캐시된 옛 화면이 보내도 장애 주입 없이 조용히 만들어지지 않게).
- `GET /api/reports?chaos=` 거르기와 `ReportSummary.chaosEnabled`·`ReportDetail.chaos`를 지운다.
- 장애 주입 실행(`source="chaos"`)은 서비스의 사용자 경로 어디에도 나오지 않는다: 목록 쿼리, 상세·PDF(`views.visible` → `404`), SSE(`sse.py`), 리포트 끝 알림(`output/alerts.sweep_finished`), 추천(`autotrade/recommend/sources` — 장애 주입 결과로 추천·모의 자동매매가 생기지 않게).
  구현할 때 `Report.objects`를 쓰는 곳을 전부 다시 확인한다 (지금 views·sse·alerts·recommend/sources·hide·budget·stats·quota·runner·auto).
- 그대로 세는 곳: 팀 AI 하루 예산(`limits/budget` — 실제 비용이 든다), 복구 지표(`autohealing/stats`, `/ops`), 실행기(`orchestration/runner` — 같은 1건씩 실행기에서 줄을 선다).

### 4-2. 내부 API (새 절)

공개 nginx(`deploy/nginx/default.conf`)는 `/api/internal/`을 `404`로 막는다. 내부 API는 web을 서버 안에만 연 `127.0.0.1:${WEB_LOCAL_PORT:-18000}`으로만 닿는다 (DB의 `DB_LOCAL_PORT`와 같은 방식, 보안 그룹에 열지 않는다).

| 메서드·경로 | 요청 | 응답 |
|---|---|---|
| `GET /api/internal/chaos-runs/options` | 서명 헤더 | `{"workers": [{"id", "title"}], "errorTypes", "scopes", "defaults": {"probability", "scope"}}` — 관리자 화면의 고르기용 (`registry.worker_ids`, `chaos.ERROR_TYPES`·`SCOPES`) |
| `POST /api/internal/chaos-runs` | `{"symbol", "chaos": ChaosConfig 요청 형식, "requestedBy": "<관리자 아이디>"}` + 서명 헤더 | `201 {"id", "status", "symbol", "name", "chaos"}` (서버가 채운 기본값·seed 포함) |

- 서명: `X-Chaos-Timestamp`(유닉스 초)와 `X-Chaos-Signature` = `hex(HMAC-SHA256(CHAOS_CONTROL_SECRET, timestamp + "." + 본문))`.
- 오류: 비밀 값이 없으면 `404`(기능 꺼짐) · 서명이 틀리거나 시각이 ±60초 밖이거나 같은 서명을 다시 쓰면 `401` (Redis `paper:chaos:sig:<서명>` 120초) ·
  `requestedBy`가 서비스의 활성 staff가 아니면 `403` · 없는 종목·잘못된 `chaos` `400` (`chaos.parse` 그대로) · 진행 중인 장애 주입 실행이 있으면 `409 {"detail", "id"}` · 팀 AI 예산 초과 `429` (`budget.check` 그대로).
- 대상 팀은 지금처럼 종목 리포트 팀(`stock_report`)만이다.

### 4-3. 백엔드

- `Report.SOURCES`에 `chaos`를 더한다 (선택지만 바뀌는 마이그레이션, DB 열은 그대로). 실행은 `user=None`이고, 신청한 관리자 아이디는 `chaos.requestedBy`에 남긴다 (`chaos.parse`가 받는 키가 아니므로 내부 API가 parse 뒤에 붙인다).
- 새 `backend/reports/autohealing/control.py`: 서명·재사용 검사, staff 확인, 실행 만들기. 뷰·경로는 Django 자리(`reports/views.py`, `/api/internal/` 경로)에 둔다 (`docs/DECISIONS.md` 29장). 세션 인증을 쓰지 않는 뷰라 CSRF와 무관하다.
- `chaos.py`(`parse`·`is_on`·`should_fail`)·`healing.py`·`orchestrator.py`는 고치지 않는다.
- `limits/quota.counts`: 사용자가 장애 주입을 켤 수 없으므로 "장애 주입이면 failed도 센다" 분기를 지우고 `source == "user"`만 센다 (D-7 문장 정리).
- 이미 있는 장애 주입 리포트(사용자가 켠 것 — 산출물 ②의 #61 등)는 데이터 마이그레이션으로 `source="chaos"`로 바꿔 서비스에서 숨긴다 (8장 C4). 관리 서버에서는 그대로 보인다.
- 설정 `CHAOS_CONTROL_SECRET` (비우면 내부 API 꺼짐): `.env.example`, `deploy/.env.docker.example`. 운영 `DJANGO_ALLOWED_HOSTS`에 터널로 오는 Host(`127.0.0.1`)가 있는지 확인한다.

### 4-4. 서비스 배포

- `deploy/docker-compose.yml` web: `ports: "127.0.0.1:${WEB_LOCAL_PORT:-18000}:8000"`.
- 서비스 서버 관리자가 한 번: `admin-tunnel`의 `authorized_keys` `permitopen`에 `"127.0.0.1:18000"`을 더하고(`admin/README.md` 7-2의 3), `.env.docker`에 `CHAOS_CONTROL_SECRET`.
- `deploy/smoke_test.sh`: 공개 주소의 `/api/internal/chaos-runs`가 `404`인지 한 줄.

## 5. 관리 서버 (`admin/API.md`를 먼저 고친다)

### 5-1. 관리자 API

- `GET /api/admin/chaos/options` — 서비스 내부 API의 options를 그대로 돌려준다.
- `POST /api/admin/chaos/runs` — `{"symbol", "chaos"}`에 로그인한 staff 아이디를 `requestedBy`로 붙여 서명해 서비스로 보낸다. 서비스의 `400·403·409·429`는 `detail` 그대로, 서비스에 닿지 못하면 `503 "서비스에 연결할 수 없습니다"`.
  **세션 쿠키로만** 부른다 — MCP 토큰으로 부르면 `403` (토큰 만들기와 같은 규칙). 감사 기록에 `event: "chaos_requested"`, `target`(만든 리포트 id 또는 실패 코드)을 남긴다.
- 장애 주입 실행 목록은 지금의 `GET /api/admin/reports?kind=chaos`를 그대로 쓴다 (`ReportRow.source`에 `chaos`가 나온다).
- 0장 공통 규칙: "쓰기는 로그인·로그아웃·MCP 토큰 만들기와 **장애 주입 신청**(서비스 내부 API로만, 서비스 DB에는 쓰지 않는다)".
- 설정: `ADMIN_CHAOS_SECRET`(서비스 `CHAOS_CONTROL_SECRET`과 같은 값, 비우면 장애 주입 메뉴가 "꺼짐"), `ADMIN_SERVICE_INTERNAL_URL`(기본 `http://tunnel:8000`).

### 5-2. 관리자 화면

- 왼쪽 메뉴에 **장애 주입**(`/chaos`, F11):
  종목 코드(6자리) · 프리셋 둘(**복구 시연** `scope: "primary"`, `probability: 0.8` / **정책 시연** `scope: "all"` — 지금 `ChaosForm` 값 그대로) ·
  직접 설정(실패 확률 · 실패 종류 · 대상 Worker · 범위 · seed) · **실행** 버튼과 확인(실제 AI 비용이 들고 팀 하루 예산에 든다). 만들어지면 리포트 상세로 간다.
  아래에 최근 장애 주입 실행 10건(`kind=chaos`).
- 리포트 상세(`/reports/:id`): `requested`·`running` 동안 3초마다 다시 받고(지금 60초) 끝나면 멈춘다. **같은 설정으로 다시**(저장된 `chaos` 그대로, seed 포함) 버튼 — 서비스 리포트 화면의 "다시 신청 (같은 장애 주입 설정)"을 옮긴 것.
- 관리 서버는 유저 앱 화면 규칙을 따르지 않으므로(`docs/DEPLOY.md` A7) `ChaosForm`을 가져오지 않고 표·폼으로 단순하게 새로 만든다 (서로 import하지 않는다). 서비스의 실시간 그래프(`PlanGraph`)는 옮기지 않는다 — 실행 기록 표가 재시도 · 대체 모델 전환 · 포기를 시간순으로 보여 준다.
- 가짜 API(MSW)와 화면 테스트.

### 5-3. MCP

- 그대로 조회 전용 9개 도구다. 장애 주입 도구는 만들지 않는다 (AI 도구가 비용이 드는 실행을 일으키지 않게). 결과는 `report_failures(kind="chaos")`·`report_trace`로 본다.

### 5-4. 관리 서버 배포

- tunnel 컨테이너(`admin/deploy/tunnel/entrypoint.sh`)에 `-L 0.0.0.0:8000:127.0.0.1:${WEB_LOCAL_PORT:-18000}`을 한 줄 더하고 compose에 `WEB_LOCAL_PORT`.
  서비스 쪽(4-4)을 먼저 바꾼다 — 거꾸로면 장애 주입만 `503`이고 DB 터널은 그대로다 (`permitopen`은 연결할 때 검사한다).
- `admin/deploy/.env.example`에 `ADMIN_CHAOS_SECRET`. `admin-ci.yml` schema 작업(읽기 전용 확인)은 그대로 통과해야 한다.

## 9. 알아 둘 것

- "완전 분리"는 켜는 곳과 보는 곳의 분리다. AI 호출이 서비스 엔진에서 도는 한 주입 판정 코드(`chaos.should_fail`)와 리포트 전용 Breaker는 서비스에 남는다.
- 관리 서버가 쓰기를 하나 갖게 되므로 "조회 전용"이라고 적은 곳을 모두 고친다 (6장). MCP 안내의 "쓰기 도구는 없다"는 그대로 맞다.
- 지금 발표·시연 흐름은 서비스 신청 화면에서 장애 주입을 켠다 (`docs/tasks/00-공통.md` 부록 A5 "화면 구성"의 발표 흐름, `docs/plans/TEAM_PAPER_TRADING_PLAN.md` 부록 A9). 구현하면 관리 서버 `/chaos` → 리포트 상세 → 복구 지표로 바꾼다.
- 관리 서버에서 누른 실행도 실제 AI 비용이 든다 (시나리오당 $0.5 안 — `docs/tasks/00-공통.md` 부록 A4 T4-10).
