# 백테스트 (AI 없음)

파이프라인의 코드 단계(선별 → 사실 검증 → 리스크 엔진 → 실행 규칙)를 과거 일봉으로 재현한다.
AI 호출과 웹 검색은 하지 않는다. AI 분석가 자리에는 규칙 시나리오(ATR 배수)를 넣는다.

```
uv run python backtest/run.py --market KR          # 기본: 2026-06-01 ~ 2026-09-30, 자본금 1000만원
uv run python backtest/run.py --market US
uv run python backtest/run.py --market KR --max-total 2000000 --start 2026-07-01
uv run python backtest/run.py --market KR --refresh   # 캐시(cache/)를 버리고 데이터를 다시 받는다
uv run pytest backtest                                  # 시뮬레이션 규칙 테스트
```

- 키움 REST API는 조회만 한다 (랭킹, 종목 정보, 일봉, 환율). 토큰은 운영과 같은 캐시(`.cache/kiwoom_token.json`)를 쓴다.
  수수료율은 모의 계좌와 같은 `PAPER_COMMISSION_KR|US`를 쓴다.
- 결과는 `results/<시장>/`에 남는다: `summary.md`, `summary.json`, `trades-N.csv`(시나리오별 판정과 결과), `equity-N.csv`.

## 재현하는 것

| 단계 | 운영 코드 | 백테스트 |
|---|---|---|
| 선별 | `screen_market` (거래대금 랭킹 1일 상위 → 30개 규칙 점수) | 유니버스 안에서 전일 거래대금 순위 → 같은 `screen.score` |
| 시나리오 | AI 분석가 3종 + 검증 + 최종 컨펌 | 규칙: 진입 = 전일 종가, 목표 = +ATR×a, 손절 = −ATR×b, 확률 0.45, 10거래일 |
| 사실 검증 | `fact_check` | 같은 함수 (보유 기간, 진입가 괴리) |
| 리스크 엔진 | `risk.assess` | 같은 함수. 자산·매수 가능 금액·총 금액 한도·유동성은 시뮬레이션 계좌로 계산 |
| 진입 | 진입가 지정가 모의 주문 (당일 유효), 같은 종목 진행 중이면 주문 안 함 | 같음. 주문일 저가가 진입가 이하면 체결 (시가가 낮으면 시가) |
| 청산 | 목표·손절·기한 조건을 확인 가격으로 2회 연속 확인하면 모의 매도 | 일봉 기준: 손절은 손절 주문가(−1%), 갭은 시가, 기한 다음 거래일 시가 |

재현하지 않는 것: AI 판단, 매수 유의 종목, 일일 손실 한도(선별이 장 전이라 당일 손실은 항상 0), 호가 단위 외 슬리피지.

## 한계

- **유니버스 편향**: 과거 시점의 거래대금 랭킹은 API로 받을 수 없다. 키움은 **당일 순위만** 준다 (토스 때의 1주~1년 순위가 없다).
  그래서 유니버스 = 당일 거래대금 상위 100 + 시장 기록(`data/trading.db`의 `rankings` 표)에 쌓인 날들의 거래대금 상위 100이다.
  기록이 쌓이기 전에는 유니버스가 당일 상위 100뿐이라 토스 때보다 좁고, 기간 중에 뜬 종목이 미리 들어가 있으며 상장폐지 종목은 빠져 있다.
  `serve`가 장 마감 후 매일의 실제 랭킹(거래대금 상위 100, 등락률 상위·하위 30)을 쌓는다 (`records/market_log.py`).
  기록이 충분히 쌓이면 그 날의 후보를 그대로 유니버스로 쓸 수 있다.
- **일봉 판정**: 같은 봉에서 손절·목표가 모두 닿으면 손절, 장중 체결일의 목표가 도달은 인정하지 않는다 (불리한 쪽).
- **AI를 빼는 이유**: 비용 외에도, 과거 날짜의 뉴스·웹 정보를 그 시점 그대로 줄 수 없고 모델이 이후 사건을 알고 있을 수 있어서
  AI 판단을 과거에 공정하게 재현하기 어렵다. 그래서 이 백테스트는 AI를 제외한 부분(선별, 리스크 엔진, 실행 규칙)을 평가한다.

## 로직 최적화 실험

진입·선별·청산·리스크·조합·새 접근 6개 실험(약 120개 변형)을 `experiments/`의 스크립트로 돌렸다.
종합 결론과 각 실험 링크는 `results/experiments/README.md`. 결론: 특정 변형을 채택할 근거는 없고, 손실의 원인은 선별된 종목
자체이며, 개선처럼 보이는 변형은 대부분 "덜 사서 덜 잃은" 효과다.

```
uv run python backtest/experiments/entry.py        # 진입 방식 (screen_rules, exit_rules, risk_regime, combo, ideas도 같은 방식)
```

실험 스크립트는 캐시만 읽는다 (`experiments/common.py`의 `load_market`). sim.py의 훅(`Settings.entry_mode`, `risk_limits`,
`Rule.trailing_atr`, `Backtest(screen_fn=, scenario_fn=, regime_fn=)`)은 모듈 docstring에 설명이 있다.

## 결과 요약 (2026-09-30 실행, 2026-06-01 ~ 09-29, 자본금 1000만원)

국내 KODEX 200은 −18.4% (7월에 −21%), 미국 SPY는 +1.2%였다. 숫자는 `results/*/summary.md`.

| 규칙 (목표·손절 ATR 배수) | 국내 | 미국 |
|---|---|---|
| AI 유사 2.0·1.5 | 0% (전부 탈락) | 0% (전부 탈락) |
| 3.0·1.0 | −18.9% | −17.0% |
| 4.0·1.5 | −17.8% | −17.8% |
| 5.0·2.0 | −9.9% | −13.5% |
| 4.0·1.5, 총 한도 200만원 | −7.8% | −4.3% |

1. **리스크 엔진은 AI 수준의 시나리오를 모두 막는다.** 실제 AI 시나리오(`runs/` 32건)는 목표 약 2.0 ATR, 손절 약 1.5 ATR,
   손익비 중앙값 1.33이다. 최소 손익비 2.0에 손절 주문가 −1%까지 반영하면 통과할 수 없다. 실제 운영 기록도 32건 중 통과 0건이다.
2. **리스크 엔진을 통과하는 규칙 시나리오는 이 기간에 손실이었다.** 목표가를 멀리 둘수록(4~5 ATR) 10거래일 안에 거의 닿지 않고
   (목표가 도달 1~5%), 대부분 손절이나 기한 청산으로 끝났다. 건당 손실은 설계대로 자산의 약 1%로 묶였다.
3. **손실의 주원인은 선별 규칙이다.** 선별된 종목을 시가에 사서 10거래일 보유하면 평균 국내 −2.2%, 미국 −1.3%였다
   (미국은 시장이 +1.2%인데도). 추세·모멘텀 점수가 이 기간에는 반대로 작동했다.
4. **진입 방식의 역선택.** 전일 종가 지정가 DAY 주문은 그날 내리는 종목만 체결된다. 체결된 종목은 이후 10일 −2.4%(국내)·−2.3%(미국),
   체결되지 않은 종목은 +0.8%·+3.3%였다.
5. **총 금액 한도는 손실을 줄였다.** 200만원 한도에서는 투자 비중이 평균 16~17%로 줄어 손실도 −4~−8%에 그쳤다.
   전략 자체의 기대값이 음수라서 생긴 효과이고, 전략이 좋아지면 반대로 수익도 줄어든다.
